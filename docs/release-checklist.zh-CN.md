# 发版前检查清单

将预发布版转为正式版之前，在真机上逐项完成本清单。

CI 只在 Linux 上的 Chromium 和 WebKit 中运行。Apple Pencil 输入、iPadOS Safari、iPad 外壳与打包后的 `.app` 只能在真机上验证。

## 0. 升级之前

- [ ] 在 Mac 上执行 `python tools/check_boards.py`，输出的最后一行应为「全部白板都能完整读出。」

> **警告**
> 如有白板会以只读白板打开，不要升级，先将输出发送给开发者。

## 1. Mac

### 升级

- [ ] 安装预发布版并首次打开。存储目录中出现 `backups/upgrade/<时间>_<旧版本>_to_<新版本>/`，其中包含 `boards/` 与 `index.json`。
- [ ] 「关于」中显示新版本号，带 `-rc` 后缀。
- [ ] 原有白板全部存在，内容、文件夹与顺序均与升级前一致。打开其中若干块，均不出现只读提示。

### 书写与编辑

- [ ] 鼠标书写、撤销、重做正常。「清空白板」在清空前要求确认。
- [ ] 对象橡皮擦与像素橡皮擦均可擦除，撤销可恢复被擦除的笔画。
- [ ] 新建大白板与笔记。将 PDF 拖入窗口新建文档板，在 PDF 上书写并导出。

### 白板选择界面与设置

- [ ] 白板选择界面中，重命名、归入文件夹、拖动排序与搜索均正常。
- [ ] 在设置中更换一次存储目录，再改回原目录，白板全部存在。
- [ ] 关闭窗口后重新打开，刚写入的内容全部存在。
- [ ] 日志文件 `~/Library/Logs/Whiteboard.log` 中每一行只出现一次。

## 2. iPad

本节执行两遍：一遍在 iPad 外壳中，一遍从主屏图标打开。

### 外壳与工具栏

- [ ] 外壳：打开后不反复弹出「有新版本」。需要更新外壳时，安装的外壳与 Mac 端版本号相同。
- [ ] 工具栏为笔具盘；此前关闭过笔具盘的 iPad 上同样为笔具盘。

### 文字输入

CI 中的浏览器无法重现 iPadOS 上输入框无法输入文字一类的问题，以下各项只能在真机上检查。

- [ ] 白板选择界面：搜索框可输入中文与英文并筛选出结果；点按白板名称可重命名；新建文件夹与重命名文件夹的输入框均可输入。
- [ ] 在 iPad 上重命名白板、尚未完成输入时，在 Mac 上重命名另一块白板。iPad 的键盘不收起，已输入的文字不丢失。
- [ ] 重命名时 iOS 不自动更正，也不将首字母改为大写。
- [ ] 新建文件夹对话框中，输入框不被键盘遮挡；键盘收起后，界面与笔具盘位置正常。

### 主屏图标

- [ ] 从主屏图标打开时，导出 PNG 可保存文件。
- [ ] 导入文档时从「照片」选择图片（包括 HEIC），结果符合预期；不支持的格式显示提示。

### 书写

- [ ] Apple Pencil：压感与倾角生效，快速书写不断笔，笔画末端不出现鼓包，手掌放在屏幕上不留痕迹（手掌屏蔽）。
- [ ] 单指平移、双指缩放；打开手指书写后，单指可书写。
- [ ] 像素橡皮擦：笔身竖直时擦除宽度小，笔身放平时宽度大；同一次拖动中宽度不变。

### 同步

- [ ] 两端同时打开时，iPad 上写的内容立即出现在 Mac 上，Mac 上写的内容立即出现在 iPad 上。
- [ ] 断开 Wi-Fi 后书写几笔，再重新连接，这几笔同步到另一端且不重复。
- [ ] 在 Mac 上退出并重新打开应用，iPad 自动重新连接，内容不丢失。

## 3. 只读白板（可选）

本节检查只读提示本身。

- [ ] 复制一块白板的 `.wbz` 文件作为备份，然后用文本编辑器修改原文件中的若干字节。
- [ ] 打开这块白板：两端均弹出只读提示，落笔改为拖动画布。
- [ ] 在 Mac 上选择「仍然编辑」：`backups/locked/` 中出现原文件的副本，两端均可继续书写。
- [ ] 用备份恢复该文件。

## 4. 发布正式版

全部检查通过后，在 `stable` 分支上推送不带后缀的 tag（例如 `v1.0.0`）。

```bash
git tag v1.0.0 && git push origin v1.0.0
```

| Tag | 发布为 | 应用内更新是否提示 |
| --- | --- | --- |
| `v1.0.0` | 正式版 | 是 |
| `v1.0.0-rc.1`（含连字符） | 预发布版 | 否 |

- CI（`.github/workflows/build-macos.yml`）构建 Mac 应用与 iPad 外壳，并将 `.zip` 与 `.ipa` 发布到 GitHub Release。
- 应用内更新读取 `releases/latest`，其中不包括预发布版。正式版发布之后，现有用户才会收到更新提示。
- Release 说明取自 `CHANGELOG.zh-CN.md` 中该版本的一节（`packaging/release_notes.py`），更新对话框显示的即为这段说明。预发布版没有单独一节时，使用对应正式版的一节；两者均不存在时，由 GitHub 自动生成说明。
