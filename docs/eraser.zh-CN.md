# 像素橡皮擦

本文说明像素橡皮擦的参数如何从 iPadOS 原生 PencilKit 实测得出、实现所用的数值，以及擦除区域的存储、同步、渲染与导出方式。

## 概要

像素橡皮擦遵循以下规则，全部依据原生 PencilKit 的实测数据。

| 规则 | 数值 | 代码 |
| --- | --- | --- |
| 直径只取决于笔身与屏幕的夹角 | 6 至 81 屏幕像素，见[直径曲线](#直径曲线) | `input-erase.js` `ERASER_CURVE` |
| 压感不参与 | 同一夹角下压感 0.15 至 0.51，直径不变 | `input-erase.js` `eraserRadius` |
| 尺寸在屏幕上恒定 | 世界半径 = 屏幕半径 / `viewport.scale`，任何缩放下均成立 | `input-erase.js` `worldRadius` |
| 整条笔画宽度不变 | 落笔时取值一次 | `input-erase.js` `startErase` |
| 鼠标、手指、无倾角数据的笔 | 取 50° 对应的直径（16.5 px） | `input-erase.js` `eraserRadius` |
| 对象橡皮擦 | 固定直径 6 px（`ERASER_TIP`） | `input-erase.js` |
| 擦除区域以遮罩存储 | 笔画 `m` 字段中的胶囊链 | `app-eraser.js` `erasePixels` |

## 数据来源

全部原生数据由 [InkProbe](https://github.com/Maimai-l/InkProbe) 采集。它在同一次落笔中让 PencilKit 正常绘制和擦除，同时记录全部原始触摸。

| 会话 | 内容 | 缩放 |
| --- | --- | --- |
| 孤立点 | 在实心墨迹上点出 21 个互不相连的擦除点，每行固定一个夹角 | 1 |
| a | 在马克笔涂成的实心区域上擦五笔，夹角 37°–43° | 1 |
| c | 在马克笔涂成的实心区域上擦两笔 | 0.25 |
| test1 | 校准 | 1 |
| test2 | 校准 | 2 |
| test3 | 拖动 | 1 |
| bench1 | 混合 | 1–3 |
| bench2 | 一笔未被 PencilKit 记录的擦除 | 0.25 |
| 原生橡皮笔画 | 92 条橡皮笔画，用于统计笔画内的夹角变化 | — |

## 测量方法

测量两个量，二者只有在橡皮接触形状为圆形时才相等。

| 量 | 方法 | 适用 |
| --- | --- | --- |
| 等效直径 | 取 `PKStroke.mask` 中每个孤立的洞的面积，换算为等面积圆的直径，再与 `input.json` 中该次落笔的 `altitudeAngle` 对应 | 孤立点 |
| 垂直宽度 | 在每个采样点处沿垂直于橡皮路径的方向测量洞的宽度，每条笔画取中位数 | 拖动笔画 |

21 个孤立点全部与落笔对应，中心偏差均小于 3 pt。以 drawing 坐标测得的数值乘以当时的缩放，得到屏幕尺寸。

## 直径曲线

`ERASER_CURVE` 把笔身与屏幕的夹角映射为橡皮直径，单位为屏幕像素。相邻点之间线性插值；大于 90° 取 6，小于 0° 取 81。

| 夹角 | 直径（px） | 依据 |
| --- | --- | --- |
| 90° | 6 | 笔尖 |
| 80° | 7.5 | 孤立点，79°–83° |
| 68° | 16.5 | 拖动宽度 |
| 37° | 16.5 | 拖动宽度，会话 a |
| 35° | 35 | 孤立点 |
| 32° | 52 | 孤立点 |
| 28° | 75 | 孤立点 |
| 25° | 81 | 孤立点，饱和 |
| 0° | 81 | 饱和 |

- 直径从 80° 开始增大，在 68° 至 37° 之间保持约 16.5，37° 以下急剧增大，25° 以下饱和于约 81。
- 常见书写握笔约为 50°，对应直径 16.5。
- 曲线单调：笔身越平，橡皮不会变窄。

> **注意**
> 37° 处的 16.5 到 35° 处的 35 之间的跃变连接了两种测量方法。按 35° 处的两个值推算，该处接触形状约为 16.5 × 75、沿笔身方向拉长的椭圆，因此在 25°–44° 范围内等效直径大于垂直宽度。37° 至 25° 之间没有拖动样本，这是曲线中最不确定的一段。

曾评估以 (37°, 16.5) 与 (25°, 81) 之间的直线代替孤立点数据，因 IoU 下降而未采用（test1 0.931 → 0.862，bench1 0.871 → 0.830）。

## 缩放

橡皮在屏幕上尺寸恒定，因此放大后在 drawing 坐标中擦除的宽度更小。命中判定和光标圈都使用 `屏幕半径 / viewport.scale`，放大和缩小两个方向均如此。

| 夹角 | 缩放 1（drawing 单位） | 缩放 2.02（drawing 单位 × 缩放） |
| --- | --- | --- |
| ~80° | 6.3–9.0 | 6.9–12.2 |
| ~50° | 15.9–18.2 | 16.9–22.8 |
| ~25° | 80.3–82.1 | 80.4–85.4 |

缩小方向依据会话 c（缩放 0.25，夹角 10.4°）：实测 80.5 个屏幕单位，曲线给出 81。`worldRadius` 对 `scale` 不设下限。

## 笔画内的宽度

橡皮宽度在落笔时确定，整条笔画不再改变，与原生行为一致。

| 原生统计（92 条橡皮笔画） | 数值 |
| --- | --- |
| 整条笔画只报告一个夹角读数的比例 | 65% |
| 笔画内极差不超过 2.36° 的比例 | 90% |
| 笔画内极差的中位数 | 0° |
| 观察到的最长起始恒定段 | 1450 个采样点的笔画中，前 648 个读数相同 |

- iPadOS Safari 报告整数度的 `tiltX` / `tiltY`，不提供 `altitudeAngle`。书写时夹角在约 33° 至 47° 之间变化，正好跨过曲线的陡峭段。若宽度随每个采样点变化，同一笔画内的直径最多相差 2.7 倍。
- 悬停时的光标圈仍随当前倾角变化，因为它只用于预览。

整条笔画固定宽度不降低准确度：

| --- | --- | --- |
| test1 | 0.934 | 0.931 |
| test2 | 0.885 | 0.878 |
| test3 | 0.902 | 0.901 |
| bench1 | 0.871 | 0.871 |

## 逐像素对照

`tools/compare_native_eraser.py` 把原生擦除区域和白板擦除区域栅格化到同一张图上，输出 IoU、多擦比例和漏擦比例。

```sh
python3 tools/compare_native_eraser.py <解压后的 InkProbe sessions 目录>
```

脚本为每个会话打印像素数，并在 sessions 目录中生成 `<名称>-diff.png`：灰色为两边都擦除，红色为仅原生擦除（漏擦），蓝色为仅白板擦除（多擦）。

### 方法

| 步骤 | 规则 |
| --- | --- |
| 墨迹区域 | 以 2 倍比例由控制点（`points`）和逐点宽度重建。不能使用 `interpolatedPoints`，因为其 `rangeIndex` 只覆盖遮罩之后仍保留的段。 |
| 原生擦除区域 | 墨迹区域减去 `final/render-transparent@2x.png` 中仍可见的墨迹（alpha > 32）。统计遮罩中的洞会遗漏被 PencilKit 拆分的笔画，而且洞可能延伸到墨迹之外。 |
| 白板擦除区域 | 沿 `coalesced` 橡皮采样点绘制胶囊，直径取第一个采样点在 `ERASER_CURVE` 上的值，除以 `viewportAtBegin` 的缩放，再与墨迹区域求交。 |
| 橡皮路径邻域 | 两边都限制在沿橡皮路径、半径为橡皮半径 3 倍的胶囊并集之内。 |
| 百分比 | 多擦与漏擦均相对于并集计算。 |

> **注意**
> 橡皮路径邻域用于排除笔画折返处的重建误差。马克笔的笔尖是 50 × 100 的扁平形状，而墨迹区域按半径 50 的圆重建，每个折返处会多出一个半圆。在会话 a 中，这部分占原生擦除总量的 47%，未加邻域限制时 IoU 从 0.91 降到 0.50。对于没有折返的会话，邻域限制只排除 0–8 px。

重建的墨迹区域整体比导出的透明底图细约 13%。

### 结果

以下结果在墨迹区域和橡皮路径邻域之内测得。

| 会话 | 缩放 | IoU | 多擦 | 漏擦 |
| --- | --- | --- | --- | --- |
| a | 1 | 0.912 | 7.4% | 1.4% |
| c | 0.25 | 0.940 | 2.2% | 3.8% |
| test1 | 1 | 0.931 | 6.5% | 0.1% |
| test2 | 2 | 0.878 | 11.5% | 0% |
| test3 | 1 | 0.901 | 9.8% | 0% |
| bench1 | 1–3 | 0.871 | 11.6% | 1.2% |
| bench2 | 0.25 | 0.003 | 99.5% | 0.2% |

多擦和漏擦比例在逐采样点宽度下测得；test1 至 bench1 的 IoU 为整笔固定宽度下的值。

### 已知异常

| 会话 | 现象 |
| --- | --- |
| a | 剩余差异集中在两条橡皮笔画的起点：原生向前多擦约一个橡皮直径，说明 PencilKit 在第一个合并采样点之前已开始擦除（预测触摸）。 |
| test2 | 第二条笔画的遮罩中有两块面积很大的负面积区域（177 × 131 和 160 × 90），而该处橡皮路径长度不超过 7 pt，输入中没有对应动作，也没有撤销。 |

## 遮罩的存储

像素橡皮擦不直接拆分笔画，而是把扫过的胶囊追加到笔画的遮罩（`m` 字段）。格式见 [format.zh-CN.md](format.zh-CN.md)。

```json
"m": [[radius, x0, y0, x1, y1, ...], ...]
```

| 规则 | 数值 | 代码 |
| --- | --- | --- |
| 新的一段接到最后一条链上 | 起点等于该链终点，且半径与该链半径相差不超过 1% | `stroke.js` `SWEEP_RADIUS_TOLERANCE`、`addMask` |
| 被覆盖的段删除 | 完全落在新胶囊内的链被移除 | `stroke.js` `addMask` |
| 客户端单条笔画上限 | `MASK_LIMIT` = 400 段胶囊 | `stroke.js` |
| 超过上限时抽稀 | Ramer–Douglas–Peucker 算法，容差 `r / 6`，与 PDF 导出相同（`inkpdf.py` `_capsules`） | `stroke.js` `simplifyMask` |
| 抽稀后仍超过上限时转换为切分 | 遮罩转换为切分，原笔画替换为切剩的几段（`remove` + `restore`）；各段沿用原层叠序号 `n` | `app-eraser.js` `bakeMask` |
| 服务端单条笔画上限 | `MAX_MASK_SEGMENTS` = 1024 段，与客户端计数方式相同 | `models.py` |

- 原生 PencilKit 同样使用遮罩：橡皮擦断一条笔画时，PencilKit 把它拆成独立的几条笔画，每条带有各自的遮罩。在白板中，看上去断成两截的笔画在转换为切分或被对象橡皮擦碰到之前，仍是一条笔画、一个 id。
- 早期设计在橡皮半径不小于笔画半宽时直接切断笔画。由于压感使半宽沿笔画变化，同一次拖动会在切断与遮罩之间来回切换，因此已去掉。
- 转换为切分会把遮罩边缘改为平直的切口，并清除贴边的细条，这是可见的变化。先抽稀可以使正常使用中不触发转换。
- `tests/test_models.py` 检查 `MAX_MASK_SEGMENTS >= MASK_LIMIT`。服务端若按不同方式计数，会截断在客户端合法的遮罩。

整屏重绘耗时随单条笔画的遮罩段数按平方增长，因此上限问题通过抽稀减少段数解决，而不是提高上限：

| 段数 | 100 | 400 | 1000 | 2000 | 4000 | 8000 |
| --- | --- | --- | --- | --- | --- | --- |
| 整屏重绘 | 0.6 ms | 2.9 ms | 15 ms | 57 ms | 229 ms | 911 ms |

对同一段来回擦除的输入，抽稀使触发转换前的采样点数从约 400 增加到约 2500（在 120 Hz 下从 3 s 以上增加到约 20 s）。

## 输入采样

橡皮擦处理的采样点与绘制相同。

| 事件 | 处理 |
| --- | --- |
| `pointerdown` | 确定本笔画的宽度，并在落笔位置擦除。 |
| `pointermove` | 沿 `getCoalescedEvents()` 返回的每个采样点擦除；只有一个时使用事件本身。每一步扫过从上一个采样点到当前采样点的线段，而不是单个点。 |
| `pointerup` | 扫过到抬笔位置的最后一段，除非该位置与最后一个采样点相同。 |
| `pointercancel` | 不补最后一段，因为该位置不代表用户抬笔的位置。 |

## 同步

遮罩变更每个动画帧发送一次，格式为 `{"op": "mask", "masks": [{id, m}]}`，内容是笔画当前的完整遮罩而不是增量。见 [protocol.zh-CN.md](protocol.zh-CN.md)。

- 客户端忽略回传的自身 `mask` 操作（`app.js` `applyOp` 中的 `context.mine`）。本地遮罩已经是最新的，回执到达时通常已包含更新的段。
- 服务端只在遮罩超过 `MAX_MASK_SEGMENTS` 时改写遮罩，该上限高于客户端上限。
- 过长的笔画在提交时切分为几条，因为服务端会丢弃超过 `MAX_POINTS_PER_STROKE`（20000）的点列。见 [protocol.zh-CN.md](protocol.zh-CN.md)。

> **注意**
> 若应用回传的遮罩，会覆盖本地更新的段，并把链拆成许多短链。在一次 120 个采样点的拖动中（应为一条链、121 个点），回执延迟为 0 ms 时产生 60 条链，延迟为 60 ms 时产生 24 条链、共 52 个点。输入回放不经过这一路径，见 [recording.zh-CN.md](recording.zh-CN.md)。

## 屏幕渲染

屏幕渲染在遮罩胶囊的并集内重新绘制背景，而不是从墨迹中减去胶囊（`renderer.js` `paintStrokes`）。

- 减法无法表达互相重叠的胶囊的并集。使用 `even-odd` 时，链上相邻两段在共用端点处的重叠区域被计算两次，因而不被擦除；使用 `nonzero` 时，被覆盖两次的区域绕数为 −2，同样不被擦除。
- 填充并集是精确的：所有胶囊子路径绕向相同，`nonzero` 填充的正是它们的并集。
- 顺序：一条笔画的遮罩覆盖该笔画及其下方的笔画。绘制一条与待补区域重叠、自身没有遮罩的笔画之前，先重绘背景，因此后绘制的笔画不会被覆盖。
- 相邻的带遮罩笔画合并为一批，统一重绘一次背景。
- 重绘的背景即白板背景：纸张和底纹、笔记的纸页，或文档板的页面。PNG 导出使用同一函数；背景为透明时改为清除该区域。

## PDF 导出

PDF 导出对每条带遮罩的笔画依次应用多条 even-odd 裁剪路径（`inkpdf.py` `mask_clips`）。

1. 以容差 `r / 6` 抽稀每条链，并展开为胶囊。
2. 把胶囊分成若干组，组内胶囊互不重叠。
3. 每组输出一条裁剪路径：笔画包围盒减去该组胶囊，随后是 `W* n`。
4. 在 `q` / `Q` 之间填充笔画。

各补集的交集等于并集的补集，因此结果是位于所有胶囊之外的笔画部分。通常需要两到三组，缺口仍为矢量路径。每条笔画只由其自身的遮罩裁剪。

## 对象橡皮擦与带遮罩的笔画

对象橡皮擦只删除它碰到的那一部分，即使该部分属于一条带遮罩的笔画（`app-eraser.js` `splitBitten`）。

1. 对每条被碰到且带遮罩的笔画，用 `bakeMask` 把遮罩转换为独立的几条笔画。
2. 对新的各段重新进行命中判定。
3. 只删除橡皮碰到的那几段。

| 情况 | 行为 |
| --- | --- |
| 橡皮经过附近但未碰到的笔画 | 不切分。 |
| 贴边的细条 | 在切分时被清除；该段随后即被删除。 |
| 遮罩没有把笔画完全断开 | 切分后仍为一段，结果与删除整条笔画相同。 |
| 撤销 | 记为一条 `split`：撤销时恢复原笔画并移除全部切分段。同一次拖动中产生又被删除的段不进入记录。 |
