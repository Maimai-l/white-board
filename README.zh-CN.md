# 局域网共享白板

供同一局域网内的 Mac 与 iPad 共同书写的手写白板。

[English](README.md) | 简体中文

## 概述

本应用运行在 Mac 上，向局域网提供手写白板页面。Mac 与 iPad 打开同一块白板，任一设备上的笔画都会实时显示在另一设备上。所有通信只在局域网内进行，不需要账号，也不使用云服务；对外连接只有检查更新：读取本项目的 GitHub Pages 站点和 GitHub Releases。

```
┌──────────── Mac ────────────┐            ┌─────── iPad ───────┐
│ pywebview 窗口（role=mac）  │            │ 主屏 Web Clip 图标 │
│   白板列表 / 背景           │  WebSocket │   全屏书写界面     │
│   缩放 / 导出 PDF、PNG      │◀──────────▶│   Apple Pencil     │
│ aiohttp 服务 + mDNS 广播    │   局域网   │                    │
│ 白板以矢量形式存储          │            │ IndexedDB 本地缓存 │
└─────────────────────────────┘            └────────────────────┘
```

## 功能

- **局域网实时同步。** Mac 提供页面并保存白板；局域网内的任何设备都可以在浏览器中打开页面并书写。
- **矢量笔迹。** 笔画以点的形式存储，而非图片。一条 500 个点的笔画通常小于 2 KB。轮廓由 [perfect-freehand](https://github.com/steveruizok/perfect-freehand) 生成。
- **Apple Pencil 输入。** 压感与倾角决定钢笔的粗细；Pencil 落下期间忽略手掌；未开启手指书写时，手指用于平移和缩放。
- **iPad 上的尺子。** 在笔具盘中打开，两指拖动和旋转，用 Pencil 沿尺边画出直线。尺子只在 iPad 上显示，画出的线照常同步。
- **形状识别。** 打开后，一笔写完笔尖停住半秒，这一笔变成直线；撤销一次回到手写的样子。默认关闭，每台设备在手指书写旁边各自打开。
- **两种橡皮擦。** 对象橡皮擦删除所触及的笔画；像素橡皮擦只移除扫过的区域，笔迹仍为矢量。
- **三种白板**，其中文档板用于在 PDF 或图片上批注，并连同笔迹一起导出。
- **白板库。** 文件夹、搜索、排序、复制和回收站；Mac 上有右键菜单、多选和快捷键，iPad 上长按打开菜单。
- **离线书写。** 笔画暂存在本地和 IndexedDB 中，连接恢复后按顺序发送。
- **权限。** 局域网内的任何设备都可以书写。管理白板、设置白板、清空白板和导出白板需要在 Mac 上分别授予。
- **速写。** 在 iPad 上随手写，在 Mac 上从 Edge 工具栏弹出的速写里复制 PNG，粘贴到 Claude 等网页；关闭即丢弃，不保存。见 [docs/sketch.zh-CN.md](docs/sketch.zh-CN.md)。

## 运行要求

| 项目 | 要求 |
| --- | --- |
| 服务端 | macOS 11 或更高版本的 Mac。Release 只提供 Apple 芯片（`arm64`）版本；Intel 机型见[自行打包](#自行打包)。 |
| iPad | Safari。Apple Pencil 不是必需的，但输入处理针对它进行了调校。 |
| 网络 | 两台设备位于同一网络，且路由器未屏蔽 mDNS / Bonjour。 |
| 从源码运行 | Python 3.10 或更高版本（Release 使用 3.12 构建）。 |

## 安装

### 下载

1. 从仓库的 Releases 页面下载 `Whiteboard-<版本号>-macos-arm64.zip`。
2. 解压后将 **Whiteboard.app** 拖入「应用程序」文件夹。

首次打开时会出现两个系统提示，每个只出现一次。

| 提示 | 操作 |
| --- | --- |
| 「无法验证开发者」 | 应用只做了 ad-hoc 签名。右键点按应用，选择「打开」，再点按「打开」。此后可以直接双击打开。 |
| 「白板想要查找并连接到本地网络上的设备」 | 必须允许，否则 iPad 无法连接 Mac。该提示自 macOS 15 起出现。 |

### 更新

1.3.0 起发布的构建通过 [Sparkle](https://sparkle-project.org) 更新。应用读取本项目 GitHub Pages 站点上的 `appcast.xml`；从前三个构建中的任一个更新时只下载变化的部分，每个下载都核对 EdDSA 签名。新版本和更新说明显示在 Sparkle 自己的窗口里；应用菜单中的「检查更新…」会打开它。

| 通道 | 何时发布 | 检查频率 |
| --- | --- | --- |
| `stable` | 每个不带连字符的 `v*` tag | 每天一次 |
| `alpha` | 每次推送到 `dev` 且所有 CI job 通过；预发布 tag（例如 `v1.3.0-rc.1`） | 每小时一次；自动下载，退出应用时安装 |

- 构建第一次启动时把自己的通道写进配置文件（`update_channel`），所以装了 alpha 的 Mac 在正式版发布后仍留在 alpha。把 `update_channel` 改成 `stable` 即可离开 alpha 通道。
- 第一次安装从 Pages 站点下载（首页列出每个通道最新的构建），或从 Release 下载。
- 更新源、增量包和签名的工作方式见 [docs/design/ci-and-updates.zh-CN.md](docs/design/ci-and-updates.zh-CN.md)。

1.2.0 及更早的版本有自己的更新方式：读取 GitHub 上的 `releases/latest`，在更新对话框中提示 1.3.0。1.3.0 起，应用只通过 Sparkle 更新。不带 Sparkle 的构建（从源码运行，或没有公钥时在本地打出的构建）不会自行更新，请用 `git pull` 或下载新版本安装。

Mac 菜单栏的应用菜单（「白板」）中依次是「关于白板」和「检查更新…」，菜单栏全部是中文。「检查更新…」直接打开 Sparkle 的窗口；从源码运行时提示用 `git pull` 更新，打包的应用没有可用的 Sparkle 时提示「这个版本不能自动更新」，原因写进日志文件。「关于白板」打开 macOS 标准的关于窗口：应用图标、名称和版本号（alpha 版在括号里显示构建时间，例如「版本 1.3.0 (alpha.20261121.150435)」；从源码运行时为 `分支@提交`），下面是「更新日志」和「日志文件」两个链接（日志文件在「控制台」中打开）。iPad 应访问的地址在「连接其他设备」中。

### 从源码运行

```bash
git clone https://github.com/Maimai-l/white-board.git
cd white-board
```

| 脚本 | 作用 |
| --- | --- |
| `start-whiteboard.command` | 首次运行时创建运行环境并安装依赖；之后直接打开窗口。 |
| `browser-mode.command` | 执行 `start-whiteboard.command --headless`：只运行服务端，通过浏览器访问。 |
| `update.command` | 执行 `git pull --ff-only`；依赖有变化时在下次启动时安装。 |

> **注意**
> 如果 macOS 拒绝打开脚本（提示「身份不明的开发者」），右键点按脚本，选择「打开」，再点按「打开」；或者执行一次 `xattr -dr com.apple.quarantine <仓库文件夹>`。

手动运行：

```bash
pip install -r requirements.txt
python run.py                 # 打开 Mac 窗口，同时在局域网上提供服务
```

| 参数 | 作用 |
| --- | --- |
| `--headless` | 只运行服务端，不打开窗口。 |
| `--port 9000` | 使用其他端口（默认 8848）。端口被占用时依次尝试下一个，最多 20 次。 |
| `--data-dir DIR` | 将白板存储在其他目录。 |
| `--mdns` | 额外注册 `_http._tcp` 服务。在 macOS 上默认由系统负责。 |
| `--no-mdns` | 不注册 `_http._tcp` 服务。 |
| `--no-bonjour` | 不注册 iPad 外壳使用的 `_whiteboard._tcp` 服务。 |
| `--debug` | 开启调试日志和开发者工具。 |
| `--version` | 显示版本号。 |

> **注意**
> `--port` 和 `--data-dir` 只对本次运行有效，不写入配置。如需长期更换存储目录，请在白板设置中选择。因端口被占用而顺延的端口同样只用于本次运行，下次启动时仍从配置的端口开始尝试。

标题栏右侧的「连接其他设备」显示 iPad 应访问的地址（格式为 `http://你的电脑名.local:8848/`）和它的二维码。

### 自行打包

推送 tag 会构建并发布 Release，其中包含同一版本的 iPad 外壳 IPA：

```bash
git tag v1.1.0 && git push origin v1.1.0
```

也可以在 Actions 页面手动运行「打包 macOS 应用」工作流；手动运行只生成构建产物，不发布 Release。本地打包：

```bash
pip install pyinstaller
python packaging/make_icns.py packaging/whiteboard.icns
WHITEBOARD_VERSION=1.1.0 pyinstaller --noconfirm packaging/whiteboard.spec
```

- 本地打包只有在 `packaging/ipad/Whiteboard.ipa` 存在时才包含 iPad 外壳；否则安装页会指向 Release 下载。
- 本地打包默认不带 Sparkle：需要先运行 `packaging/fetch_sparkle.sh` 和 `packaging/embed_sparkle.sh dist/Whiteboard.app`，再运行 `packaging/sign_app.sh dist/Whiteboard.app`；没有设置 `SPARKLE_FEED_URL` 和 `SPARKLE_PUBLIC_ED_KEY` 时不会自行更新。
- Intel 版本需要在 Intel Mac 上本地打包，或把 `.github/workflows/ci.yml` 中 `package` job 的机器换成 `macos-13` / `x86_64`。
- 将预发布版转为正式版之前，按照 [docs/release-checklist.zh-CN.md](docs/release-checklist.zh-CN.md) 逐项检查。

打包后的应用与源码运行共用 `~/Library/Application Support/Whiteboard`，两者之间切换不会丢失白板。打包后的应用将日志写入 `~/Library/Logs/Whiteboard.log`。

## 连接 iPad

在 Mac 窗口中点按标题栏右侧的「连接其他设备」，按钮下方弹出一个面板：

| 部分 | 内容 |
| --- | --- |
| 二维码 | 白板地址的二维码。用 iPad 的相机扫描，即在 Safari 中打开白板。 |
| 地址 | 例如 `你的电脑名.local:8848`，旁边的「拷贝」把完整地址拷贝到剪贴板。 |
| 已连接 | 打开了白板的其他设备（`iPad` 或 `浏览器`）；没有时显示「没有连接的设备」。 |
| 在 iPad 上安装白板 | 二维码换成 [iPad 外壳](#ipad-外壳)的安装页地址；再点「扫码连接白板」换回来。 |
| 存储描述文件 | 保存[主屏描述文件](#主屏描述文件)。 |

- 有其他设备连接时，「连接其他设备」的图标显示为蓝色。设备连上或断开时，窗口中出现一条提示，例如「iPad 已连接」「iPad 已断开」。
- 「连接其他设备」只出现在 Mac 窗口中。点外面、按 Esc 键或再点一次按钮即关闭面板。
- 连点「连接其他设备」三下打开诊断面板，见[诊断面板](#诊断面板)。

### 主屏描述文件

1. 在 Mac 窗口中点按「连接其他设备」，再点按面板下方的「存储描述文件」，保存 `whiteboard.mobileconfig`。也可以在 iPad 的 Safari 中直接打开 `http://你的电脑名.local:8848/profile.mobileconfig`。
2. 在 iPad 上打开该描述文件，然后进入「设置」→「已下载描述文件」→「安装」。描述文件未签名，确认安装即可。
3. 主屏上出现「白板」图标。点按后以全屏打开白板，不显示 Safari 的地址栏。

描述文件使用 `.local` mDNS 主机名，因此 Mac 的 IP 地址变化后无需重新安装。该主机名由 macOS 自带的 Bonjour 服务发布；`--mdns` 只是为发现工具额外注册 `_http._tcp` 服务，注册失败不影响使用。

### iPad 外壳

iPad 外壳是可选的原生应用，内含一个 `WKWebView`。它加载 Mac 上的同一个页面，并把 UIKit 的 Pencil 采样点传给页面。白板的全部逻辑都在页面中，因此 Mac 端更新后，外壳在下次打开时即使用新的行为。

| 输入途径 | 每秒新的 Pencil 位置 | 坐标 | 预测采样点 |
| --- | --- | --- | --- |
| Safari | 约 60 个 | 整数 | 无 |
| iPad 外壳 | 约 240 个 | 带小数 | 有 |

外壳通过 TrollStore 安装，因此 iPad 的系统版本必须在 TrollStore 支持的范围内：iPadOS 14.0 beta 2 至 16.6.1、16.7 RC 或 17.0。没有 TrollStore 时请使用主屏描述文件，功能相同。

1. 在 Mac 窗口的「连接其他设备」面板中点按「在 iPad 上安装白板」，二维码换成外壳安装页 `http://你的电脑名.local:8848/ipad`。用 iPad 的相机扫码，或在 iPad 的 Safari 中打开该地址。
2. 在 TrollStore 的设置中开启 URL Scheme，然后点按「安装白板外壳」。
3. 打开外壳。局域网中只有一台 Mac 时直接连接；有多台时列出供选择。路由器屏蔽 Bonjour 时，回到安装页点按「打开外壳」。

- **更新。** Mac 更新后，外壳在下次启动时提示更新，并将安装包交给 TrollStore 安装。
- **更换 Mac。** 在右上角的连接状态中点按「换一台 Mac」，或在 iPadOS「设置」App 的「白板」中开启「重新查找 Mac」。两种方式下外壳都会列出找到的 Mac，即使只有一台，以便确认。
- **发现。** Mac 通过系统的 mDNS 服务注册 `_whiteboard._tcp`。`--no-bonjour` 关闭该注册，此后只能从安装页进入外壳。
- **导出。** 外壳将导出的文件作为下载接收，并打开系统分享面板，可存入「文件」或发送。

设计与验收标准见 [docs/ipad-shell.zh-CN.md](docs/ipad-shell.zh-CN.md)。

## 使用

### 窗口

界面采用系统控件的样式：磨砂玻璃和系统蓝强调色。外框按设备分两种。每个入口只在设备拥有相应权限时显示：「白板库」需要「管理白板」，「导出」需要「导出白板」，「白板设置」需要「设置白板」（Mac 窗口和 iPad 外壳中始终显示）。

**Mac 窗口与电脑上的浏览器**

- **标题栏（顶部）：** 左边是「白板库」按钮和白板名称，名称下方是白板所在的文件夹。右边依次是「连接其他设备」（只在 Mac 窗口中，见[连接 iPad](#连接-ipad)）、「导出」和「白板设置」。在 Mac 窗口中这一条就是窗口的标题栏：关闭、最小化、缩放三个按钮在它的左端；拖动空白处移动窗口，双击空白处缩放窗口（或者最小化，按「系统设置 → 桌面与程序坞」中的设置）。白板库的顶栏也一样。
- **工具栏（底部正中）：** 见下文。
- **缩放（右下角）：** 「缩小」、当前比例、「放大」和「回到内容」。点按比例（例如 `100%`）回到实际大小。
- **连接状态：** 电脑上的浏览器与 Mac 断开时，白板名称旁出现一个红点，正在连接时为黄色，连接正常时不显示。Mac 窗口中没有这个点。

**iPad 与其他触摸设备**

- **左上角：** 返回按钮「白板库」。
- **右上角：** 连接状态、「导出」和「白板设置」。连接状态的图标连上 Mac 时为蓝色，未连接时为灰色；点按后显示「已连接」或「未连接」和 Mac 的地址，在 iPad 外壳中另有「换一台 Mac」。快速连点三下打开诊断面板。
- **工具栏：** iPad 上是笔具盘，其他触摸设备上是普通工具栏。触摸设备上没有缩放控件，用双指缩放。
- 笔具盘挪到右上角那组按钮上时，这组按钮暂时淡出，挪开后回来。

### 工具栏

iPad 使用**笔具盘**；其他设备使用**普通工具栏**。满足以下任一条件的设备视为 iPad：User-Agent 含 `iPad`；报告 `Macintosh` 且触摸点多于一个（iPadOS 的 Safari 使用桌面版 User-Agent）；页面运行在 iPad 外壳中。两种工具栏之间不能切换。

| | 笔具盘（iPad） | 普通工具栏（其他设备） |
| --- | --- | --- |
| 工具 | 钢笔、马克笔、荧光笔、橡皮擦；每件工具分别记录颜色和粗细 | 钢笔、马克笔、荧光笔、橡皮擦 |
| 颜色与粗细 | 点按正在使用的工具打开粗细面板；点按彩虹色块打开取色器 | 「颜色与粗细」：8 种颜色、5 档粗细；选中橡皮擦时改为选择对象橡皮擦或像素橡皮擦 |
| 其他控件 | 撤销、重做、尺子；「⋯」菜单中有自动最小化、手指书写、形状识别和清空白板 | 「撤销」「重做」和「更多」菜单 |
| 位置 | 停靠在四条边中的任意一条，或在角落缩为圆形 | 底部或左侧，记录在本机；面板向远离边缘的方向展开 |

普通工具栏的「更多」菜单：

| 项目 | 说明 |
| --- | --- |
| 手指书写、形状识别 | 开关，只在没有笔具盘的触摸设备上出现。 |
| 回到内容 | 与缩放控件中的「回到内容」相同。 |
| 清空白板… | 确认后清除整块白板，需要「清空白板」权限。 |

笔具盘采用 [static/vendor](whiteboard/web/static/vendor/README.md) 中的实现，并增加了以下功能：

- 点按正在使用的工具打开粗细面板；点按彩虹色块打开完整的取色器（色板、色谱、滑块）。
- 拖动握把可将笔具盘停靠到四条边中的任意一条；上边沿用下边的布局，面板向下展开。在某条边的触发区内停留 250 ms 后，该边成为停靠目标。快速拖动后松手时，笔具盘按惯性越过松手位置继续移动；动画可在任意时刻中断。相关参数位于 `static/js/pkpicker.js` 顶部的 `TUNING`。
- 放到角落时，笔具盘缩为显示当前工具的圆形，Pencil 或光标靠近时自动展开。手指没有悬停状态，需点按圆形。
- 撤销和重做使用白板自身的历史记录，按钮状态随之变化。
- 白板库打开时，笔具盘隐藏。
- 未使用原实现自带的画布、直尺和套索。保留了原实现的尺子按钮，打开的是白板自己的尺子，外观与原实现的直尺相同（见[尺子](#尺子)）。不透明度不可用，因为笔画格式中没有对应字段。

书写期间关闭背景模糊。笔具盘始终不使用磨砂效果，因为它位于书写区域之上。

### Pencil、手指与手掌

| 输入 | 行为 |
| --- | --- |
| Apple Pencil | 书写。默认只有 Pencil 可以书写。 |
| 手指（默认） | 单指或双指平移、缩放。 |
| 手指（开启手指书写） | 单指书写，双指平移、缩放。第二根手指落下时，撤回刚开始的笔画。该设置记录在本机。 |
| 手掌 | Pencil 落下期间及抬起后 0.5 s 内忽略。手掌先于 Pencil 接触屏幕造成的位移，在 Pencil 落下时撤回。 |

- 钢笔的粗细随压感和倾角变化。马克笔和荧光笔粗细一致；荧光笔半透明。
- 压感曲线按 iPad 实际报告的范围拟合：一整行手写的压感落在 0 至 0.13 之间。见 [docs/format.zh-CN.md](docs/format.zh-CN.md)。
- 页面在画布上屏蔽 Safari 的文字选择、查询和长按手势，否则快速书写时这些手势会接管笔画。
- 文本输入框（白板名称、搜索、文件夹名称）可以正常输入文字。

### 尺子

笔具盘中的尺子按钮在 iPad 上显示或收起一把尺子，用法与 iPad 自带应用中的尺子相同。尺子只存在于这台 iPad：不同步，Mac 上不显示，重新载入页面后收起。沿尺子画出的线与其他笔画一样同步。

| 输入 | 行为 |
| --- | --- |
| 单指按在尺子上 | 拖动尺子。 |
| 双指按在尺子上 | 拖动并旋转尺子。转动时尺子上显示尺边与水平线的夹角（0° 至 90°），停下后不久淡出；接近 45° 的整数倍 2° 以内时吸附到该角度。 |
| 手指在尺子外落下 | 照常平移、缩放画布。第一根手指在尺子上、第二根落在尺子外时，两指一起平移、缩放画布。 |
| Pencil 在尺子上或距尺边 24 pt 以内起笔 | 沿该尺边画线：笔画的每个点都在尺边所在的直线上。距离按屏幕计算，不随缩放变化。 |
| Pencil 在更远处起笔 | 照常书写。 |

平移或缩放画布时，尺子在屏幕上的位置不变；沿尺子画线的过程中尺子保持不动。开启手指书写时，在尺边附近起笔的手指笔画同样贴边。

### 橡皮擦

在橡皮擦面板中选择橡皮擦；选择记录在本机。两种橡皮擦都不能手动调节粗细。粗细以屏幕像素为单位，因此放大后擦除范围更精细。

| 橡皮擦 | 行为 | 直径 |
| --- | --- | --- |
| 对象橡皮擦（默认） | 删除所触及的笔画。若该笔画已被像素橡皮擦分成多段，只删除触及的那一段。 | 6，与角度无关 |
| 像素橡皮擦 | 移除扫过的区域，保留其余部分。 | 由 Pencil 落下时笔身与屏幕的夹角决定 |

像素橡皮擦的直径取自 `packages/inksync/inksync/web/input-erase.js` 中的 `ERASER_CURVE`，数值根据原生 PencilKit 测得。表中各点之间按线性插值。

| 笔身与屏幕的夹角 | 90° | 80° | 68°–37° | 35° | 32° | 28° | ≤ 25° |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 直径（屏幕 px） | 6 | 7.5 | 16.5 | 35 | 52 | 75 | 81 |

- 粗细在 Pencil 落下时确定，同一笔画内不再变化；悬停时的光标圈仍随倾角变化。常规握笔姿势约为 50°，对应直径 16.5。鼠标和手指没有倾角，使用 50° 对应的数值。
- 夹角根据 `tiltX` / `tiltY`（Pointer Events Level 2）按规范附录中的公式计算。只有两者都为 0 时才使用 `altitudeAngle`，因为不支持倾角的浏览器会将其报告为 π/2（竖直）。
- 像素橡皮擦将扫过的区域作为遮罩记录在笔画上（文件格式中的 `m` 字段）。渲染和导出 PDF 时从轮廓中减去遮罩，因此笔迹保持矢量。
- 某条笔画的遮罩在抽稀后仍超过上限时，该笔画被替换为剩余的若干段，并保留原有的层叠顺序。一次拖动为一个撤销步骤。

擦除的开销取决于扫过的区域，与笔画总数无关：笔画按 256 单位的网格建立空间索引，只重绘脏矩形，一次拖动产生的操作每帧发送一次。脏矩形重绘的结果与整屏重绘逐像素一致。

| 白板规模 | 橡皮擦 | 擦除一次，优化前 → 优化后 |
| --- | --- | --- |
| 3000 条笔画 | 对象橡皮擦 | 438 ms → 4.4 ms |
| 3000 条笔画 | 像素橡皮擦 | 465 ms → 13 ms |
| 6000 条笔画 | — | 854 ms → 28 ms |

测量方法与细节见 [docs/eraser.zh-CN.md](docs/eraser.zh-CN.md)、[docs/format.zh-CN.md](docs/format.zh-CN.md)。

### 鼠标、触控板与键盘

| 输入 | 操作 |
| --- | --- |
| 左键 | 书写 |
| 中键、右键或按住空格键 | 平移 |
| 滚轮 | 滚动 |
| ⌘ / Ctrl + 滚轮 | 缩放 |
| 触控板双指捏合 | 缩放 |
| `⌘Z` | 撤销 |
| `⌘⇧Z` / `⌘Y` | 重做 |

点按「白板设置」，按钮下方弹出一个面板。点外面、按 Esc 键或再点一次按钮即关闭。面板按设备显示以下几段：

| 其他设备可以 | 其他设备的权限开关：管理白板、设置白板、清空白板、导出白板，见[其他设备的权限](#其他设备的权限) | Mac 窗口 |

### 白板库中的设置

白板库边栏最下面的「设置」把整个应用的设置放在一页上，不用先打开一块白板。Mac 窗口中依次是「连接其他设备」（二维码、地址和「拷贝」、已连接的设备，以及安装 iPad 外壳和存储描述文件的链接）、「其他设备可以」、「存储位置」，装有应用时还有「首页」。其他设备上这一页显示连接：所连 Mac 的地址，iPad 外壳中另有「换一台 Mac」。白板设置面板里保留同样的开关，方便随手改。

### 白板类型

白板类型在新建时选定，之后不能更改。新建白板时选「向下延伸」得到笔记，选「四向延伸」得到大白板；文档板由导入的 PDF 或图片生成。

| 类型 | 范围 | 初始视图 |
| --- | --- | --- |
| 大白板（四向延伸） | 四个方向无限延伸；缩放范围 0.05×–8× | Mac 上适应内容，iPad 上 1:1 |
| 笔记（向下延伸） | 宽度为一页（1000 单位），向下无限延伸 | 页宽，位于页首 |
| 文档板（beta） | 范围固定，由 PDF 或图片生成 | 页宽，位于首页 |

- 在笔记中，不能在页面之外书写；在页边拖动即翻页，视图不能越过页首。
- 翻页速度超过约 350 px/s 时按惯性继续移动。一页接近占满屏幕宽度时，松手后缩放自动对齐到页宽。
- 「回到内容」在右下角的缩放控件中，也在工具栏的「更多」菜单中。

### 白板库

点按「白板库」（Mac 上在标题栏左边，iPad 上在左上角）打开白板库，需要「管理白板」权限。打开时停在当前白板所在的文件夹（不在文件夹中时停在「最近」），并选中当前白板。

**边栏**

| 项目 | 内容 |
| --- | --- |
| 最近 | 全部白板按修改时间分为「今天」「本周」「更早」三组。 |
| 全部白板 | 全部白板，后面是块数。 |
| 文件夹 | 每个文件夹一行，后面是块数，按名称排序。 |
| 应用 | 已安装的应用各占一行，按页列出应用的白板，点按以只读方式查看。只在装有应用时出现。 |
| 回收站 | 移到回收站的白板，后面是块数。 |

在 iPad 上，边栏可以用左上角的按钮隐藏和显示；屏幕较窄时默认隐藏，选好一项后自动收起。

**顶部**

- 标题，选中多块时后面显示「已选择 N 项」。
- 显示方式：图标（缩略图网格）或列表（名称、文件夹、修改时间三列）。选择记录在本机。
- 排序方式：「修改时间」「名称」或「手动排列」，记录在本机。「最近」和「回收站」中没有排序方式。
- 搜索框：按名称、默认名称、文件夹名称和文档的原文件名搜索全部白板，结果不分文件夹列出。按 Esc 键清空搜索。
- 「新建白板」：弹出两个选项，「向下延伸」新建笔记，「四向延伸」新建大白板。在文件夹中新建的白板放在该文件夹里。在回收站中，这个按钮换成「清空回收站」。

**白板卡片**显示缩略图、名称、类型图标（向下延伸、四向延伸或文档）和时间。时间是最后一次书写的时刻：当天只显示时刻，前一天显示「昨天」加时刻，当年不显示年份。未命名的白板显示默认名称（「白板」「笔记」）；由 PDF 或图片创建的白板以原文件名（不含扩展名）命名。

| 操作 | Mac | iPad |
| --- | --- | --- |
| 选中 | 单击；⌘ 单击加选或取消 | — |
| 打开 | 双击，或选中后按回车键、⌘O | 点按 |
| 菜单 | 右键点按 | 长按不动后松开 |
| 拖动 | 按住拖动 | 长按后移动 |

白板的菜单：

| 项目 | 说明 |
| --- | --- |
| 打开 | 打开这块白板。 |
| 重命名 | 名称变为输入框。按回车键或点按其他位置确认，按 Esc 键取消，清空名称则恢复默认名称。输入法组字期间的回车键和 Esc 键由输入法处理。 |
| 移到文件夹 ▸ | 子菜单：「不放在文件夹中」、各个文件夹和「新建文件夹」。「新建文件夹」新建一个文件夹并把白板移进去，名称直接进入编辑状态。 |
| 复制 | 得到一块笔迹、背景和文件夹都相同的副本，排在原白板之后，名字是原名字加「 副本」，例如「讲义 副本」；文档板连同原件一起复制。当前白板不变。 |
| 导出… | 切换到这块白板并打开导出对话框，需要「导出白板」权限。 |
| 移到回收站 | 不需要确认。 |

选中多块白板时，菜单只有「移到文件夹」和「移到回收站」，作用于全部选中的白板。任何白板都可以在不切换到该白板的情况下重命名；重命名只广播列表。

在空白处右键点按，菜单中有「新建白板」（⌘N）、「新建文件夹」（⇧⌘N）、「导入 PDF 或图片…」（⌘I）以及「以图标显示」「以列表显示」。其他快捷键：

| 按键 | 作用 |
| --- | --- |
| 回车键、⌘O、⌘↓ | 打开选中的那块白板 |
| ⌘⌫ | 将选中的白板移到回收站 |
| ⌘F | 跳到搜索框 |
| Esc | 先取消选中，再按一次关闭白板库 |

**文件夹**只有一层，显示在边栏中。

- 新建文件夹：点按边栏「文件夹」旁的「+」，或按 ⇧⌘N。与访达相同，新文件夹的名称框直接进入编辑状态并选中默认名称「未命名文件夹」：输入名称后按回车键或点按其他位置即完成，按 Esc 键保留默认名称。名称已存在时显示「已经有同名的文件夹了」，按回车键时保持编辑状态。
- 文件夹的菜单（右键点按，iPad 上长按）：「重命名」「在此新建白板」「删除文件夹」。双击文件夹也可以重命名，按 Esc 键取消。
- 文件夹以名称作为标识。重命名文件夹会同时修改其中每块白板记录的文件夹名称；不能使用已存在的名称。
- 删除文件夹前会请求确认。其中的白板不会被删除，仍在「全部白板」中，只是不再属于任何文件夹。回收站里的白板保留原文件夹的名称，恢复时重新建立该文件夹并放回其中。

**拖动**卡片可以整理白板；列表显示时拖动行首的缩略图。把选中的多块白板之一拖到边栏上时，所有选中的白板一起移动。

| 放置位置 | 结果 |
| --- | --- |
| 边栏中的文件夹 | 移入该文件夹。 |
| 边栏中的「全部白板」 | 移出文件夹。 |
| 边栏中的「回收站」 | 移到回收站。 |
| 两块白板之间 | 调整顺序。只在排序方式为「手动排列」、不在「最近」和回收站中、没有搜索时可用；只有指针在同一位置停留后，其他卡片才会让位。 |
| 靠近上边或下边 | 滚动列表。 |

- 鼠标和触控板移动数个像素即开始拖动；手指和 Pencil 需要横向移动，或按住卡片不动 220 ms，纵向滑动为滚动列表。
- 顺序保存在 Mac 上的 `space.json` 中，因此所有设备上一致，重启后保留。
- 拖动基于指针事件实现，未使用浏览器的拖放功能，因为 iOS Safari 不支持该功能。时间参数和弹簧曲线位于 `static/js/dragsort.js` 开头。
- `static/lab/drag.html` 是用于在 iPad 上调整上述参数的独立页面。它只在从源码运行时可用；打包后的应用不包含 `static/lab/`。

**回收站。** 移到回收站的白板显示在边栏的「回收站」中，按移入的时间排列，卡片上显示删除时间。菜单中有「恢复」（放回原来的文件夹）和「永久删除」；「清空回收站」永久删除其中全部白板。把回收站中的白板拖到边栏的文件夹或「全部白板」上，也会恢复并放到那里。在回收站中超过 30 天的白板会在应用启动时以及运行期间每小时彻底删除一次。回收站中的白板不会成为当前白板：删除当前白板时，所有设备切换到第一块不在回收站中的白板，若没有则切换到一块新建的空白板。从访达打开回收站中某块白板的 `.wbz` 文件会将其恢复。

### 文档（PDF 与图片）

将 PDF 或图片拖入窗口、在白板库空白处的菜单或「新建白板」面板中选择「导入 PDF 或图片…」（⌘I；iPad 上从「新建白板」面板导入），或在访达中用本应用打开文件，即可新建文档板（beta）。页面依次排列在画布上，已连接的设备同步切换到新白板。

- 一次可以拖入或选择多个文件，每个文件新建一块白板，最后停在最后一块上。
- PDF 多于 1 页时先弹出导入对话框：左边一栏是每一页的缩略图，点一下选上或取消；右边选「全部」「范围」（写法和导出一样，例如 `3-15` 或 `1-3, 8`）或「所选的页」，勾选「每页后面加一页空白」则每页后面跟一页同样大的空白页。按钮写「导入 N 页」，按「取消」或 Esc 什么都不建。单页的 PDF 和图片直接建板。
- 拖着文件经过窗口时，界面上显示「导入为新白板」，白板库中显示某个文件夹时为「导入到 <文件夹>」。
- 新白板放在哪里：白板库打开时，放入当前显示的文件夹；文件放在边栏的某个文件夹上时，放入那个文件夹；白板库关闭时，放入当前白板所在的文件夹。从访达打开的文件同样放入白板库当前显示的文件夹或当前白板所在的文件夹。

**空白页。** 批注写不下时可以在文档板里加空白页，需要「管理白板」权限：

- Mac 上右键点按一页，触摸设备上手指按住一页不动（打开「用手指绘图」时手指在写字，不认长按），菜单里有「在后面插入空白页」「在前面插入空白页」；空白页上还有「删除这一空白页」，删除前先确认，上面写的会一起删除。原件的页不能删。
- 工具栏的「更多」菜单（iPad 上是笔具盘的「…」）里有「在这一页后面插入空白页」，加在屏幕中间那一页后面。
- 空白页和旁边那一页一样大，底纹跟着白板设置里的「背景」。后面各页连同上面的笔迹一起往下移，所有设备马上看到新的页；加页或删页之后撤销记录清空。

**从访达打开文件。** 打包后的应用出现在 PDF、png、jpeg、gif、bmp、webp 和 tiff 文件的「打开方式」中，作为备选应用，不改变系统默认的打开方式。`.wbz` 文件归本应用所有，双击即可打开。

| 文件 | 结果 |
| --- | --- |
| PDF 或图片 | 新建文档板，与拖入窗口相同；多于 1 页的 PDF 先弹出导入对话框。 |
| 当前存储目录中的 `.wbz` | 切换到该白板。 |
| 其他 `.wbz`（例如 `backups/` 中的文件） | 导入为新白板，原文件不作修改。无法完整读取的白板以只读方式打开。文档板还需要同一存储目录的 `docs/` 中存有原件。 |

| 项目 | 说明 |
| --- | --- |
| 格式 | PDF、png、jpg/jpeg、gif、bmp、webp、tif/tiff |
| 限制 | 一块白板最多 400 页（空白页也算）；导入对话框列出 PDF 的前 5000 页，更长的 PDF 提示拆开导入；上传文件最大 256 MB |
| 不支持 | 设有密码的 PDF |
| 原件 | 原样复制到存储目录的 `docs/` 中，不作任何修改 |
| 笔迹 | 以矢量数据保存在白板的 `.wbz` 文件中；不能写在页面之外；视图止于首页和末页 |
| 页面图像 | 由 Mac 按缩放档位渲染，只渲染可见的页面 |

导出对话框（见[导出](#导出)）使用白板上的页：导入时选的原件页面和加的空白页，按白板上的顺序。PDF 原件保留原有页面并追加笔迹；图片原件导出为 PDF，或按所选清晰度导出为 PNG；空白页带着白板的背景底纹导出。

- 导出 PDF 时，笔迹以矢量形式追加，原有内容不重新编码。每条笔画使文件增大数百字节；批注较多的讲义增大数百 KB。
- 两页之间空隙中的笔迹归入较近的一页；页面之外的笔迹被裁掉。

### 导出

「导出」（Mac 上在标题栏右侧，iPad 上在右上角）打开导出对话框，需要「导出白板」权限。白板库中白板菜单的「导出…」先切换到那块白板，再打开导出对话框。对话框左边一栏是要导出的内容，右边是选项。

| 部分 | 行为 |
| --- | --- |
| 左边一栏 | 按页导出时是每一页的缩略图，下沿有一颗勾选胶囊，写着页码，例如 `1 / 7`。点一下选中或取消选中，「页面」随之换成「所选的 N 页」。上方显示「已选 N 页」、「全选」链接（全部选中时变为「取消全选」）和「当前页」（只选视口中间那一页）。整张长图时显示整块白板的预览，WBZ 时显示文件名。 |
| 格式 | PDF、PNG 或 WBZ。选 PNG 时，选中一页得到一个 PNG 文件，选中多页得到一个压缩包，每页一个 PNG，按页序命名。WBZ 是白板文件：原样下载这块白板的 `.wbz` 文件，在应用里打开（Mac 上双击）就是同一块白板。导出按钮跟着格式写成「导出 PDF」「导出 PNG」「导出 WBZ」。 |
| 范围（大白板和笔记） | 「按页」按页导出；「整张长图」不分页，整块白板导出为一页 PDF 或一张 PNG，大小是全部墨迹加四周留白。 |
| 页面 | 「全部 N 页」；「范围」加输入框里写的页码，例如 `1-5, 8, 11-13`（用 , 、 ; 或空格隔开）；或「所选的 N 页」，即在左边一栏点选的页。输入框和缩略图的选中互相跟随。写了不存在的页码时，输入框下面给出提示，导出按钮变灰。 |
| 清晰度（仅 PNG） | 标准 150 dpi、高 300 dpi（默认）、最高 600 dpi。下面一行显示像素尺寸；超过 4000 万像素时和服务端一样降低清晰度。 |
| 纸张 | 跟随内容（默认）：每页的纸就是页框加四周留白，字不缩小。A4 或 Letter：竖放的纸，页框等比放进去。 |
| 分页 | 页数（「自动分成 N 页」，调整过之后是「手动分成 N 页」），以及「调整…」按钮。 |

- 白板的 1 个单位印为 1 pt，页面上笔迹的大小与 100% 缩放时看到的一致。PDF 页面为矢量，任意放大都清晰；PNG 按所选清晰度渲染，与白板铺得多开无关。
- 自动分页：大白板从上往下分，每页的宽度取这一段内容的宽度，尽量切在两行之间。笔记按纸张长度往下切，尽量切在两行之间。文档板使用原件的页面。
- 「调整…」在白板上显示各页的页框：拖动页框移动，拖动角上的控制点缩放（选了 A4 或 Letter 时保持纸张比例），用删除按钮删掉一页。在页框之外的白板上用一根手指、Pencil 或鼠标拖动，拖出一个新页框；选了 A4 或 Letter 时它保持纸张比例，按拖动的形状横放或竖放。「清空」删掉所有页框，「添加一页」在视图中央加一页，「自动分页」恢复自动分页，「完成」回到对话框。两根手指、滚轮和触控板照常平移缩放白板，不会落笔。
- 在 Mac 窗口中通过保存对话框保存文件；其他设备上直接下载（iPad 外壳会打开共享面板）。

## 其他设备的权限

任何打开该地址的设备都可以书写。其他所有操作都需要在 Mac 的白板设置中逐项授予，默认均不授予。

| 权限 | 允许的操作 | 服务端检查位置 |
| --- | --- | --- |
| 管理白板 | 打开白板库；切换、新建、复制、重命名、归入文件夹、移到回收站、恢复、永久删除、由 PDF 或图片新建、文档板加删空白页 | `/api/info`、`/api/boards`、`/api/thumb`、`/api/doc` 上传和暂存、`/api/board/<id>/pages`，以及对应的 WebSocket 操作 |
| 设置白板 | 更换背景 | `meta` 操作 |
| 清空白板 | 一次清除整块白板 | `clear` 操作 |
| 导出白板 | 下载整块白板，包括原件 | `/api/export` |

- 权限根据 TCP 对端地址判断。回环地址和 Mac 自身的局域网地址拥有全部权限。不使用 User-Agent 和 WebSocket 握手中的 `role`，因为客户端可以任意填写这两项。WebSocket 的权限在连接建立时确定。
- 每个请求还要检查来源：浏览器里其他网页发来的请求（带着其他网站的 `Origin`），以及 `Host` 不是 IP 地址、`localhost`、`*.local` 或本机主机名的请求，一律返回 403。否则 Mac 上打开的任意网页都能以本机的身份读取或删除白板。用其他域名（例如 VPN 分配的域名）打开白板时，把它加到配置文件（`~/Library/Application Support/Whiteboard/config.json`）的 `allowed_hosts` 中，例如 `"allowed_hosts": ["mac.example.ts.net"]`，然后重启应用。详见 [docs/protocol.zh-CN.md](docs/protocol.zh-CN.md#请求来源)。
- 书写始终允许：页面、WebSocket、页面图像、描述文件和诊断上报不需要权限。
- 页面通过 `data-perms` 属性获得已授予的权限，只显示允许的入口。这只影响显示；权限由服务端检查。
- 检查更新和选择存储目录通过本机的 pywebview 接口进行，其他设备无法访问。因此「连接其他设备」只出现在 Mac 窗口中，「关于白板」和「检查更新…」只在它的菜单栏里。

## 数据

### 存储结构

默认存储目录为 `~/Library/Application Support/Whiteboard/boards-data`，可在白板设置中更改。

```
boards-data/
  boards/<id>.wbz        每块白板一个文件
  index.sqlite           白板列表的索引（可重建）
  space.json             顺序、文件夹名称和当前白板
  spaces/<应用名>/        已安装应用的白板，结构同上
  apps/<应用名>/          已安装的应用（见 docs/embed.zh-CN.md）
  thumbs/<id>.png        白板库的缩略图
  docs/<id>.<ext>        文档板的原件
  backups/upgrade/       新版本首次运行前的副本
  backups/locked/        编辑只读白板前的副本
```

| 路径 | 说明 |
| --- | --- |
| `boards/<id>.wbz` | 点经过量化、增量编码和 varint 编码；文件整体经 zlib 压缩。格式见 [docs/format.zh-CN.md](docs/format.zh-CN.md)。 |
| `index.sqlite` | 删除后下次启动时从 `.wbz` 文件重建。启动时按修改时间核对文件与索引，应用关闭期间被改动或放入的文件也会更新到索引中。 |
| `space.json` | 顺序、文件夹名称和当前白板。删除后顺序按更新时间排列；包含白板的文件夹可以恢复，空文件夹不能恢复。 |
| `spaces/<应用名>/` | 删除应用（`apps/<应用名>/`）后保留，重新安装同名应用后恢复。 |
| `thumbs/<id>.png` | 由 Mac 上传。文档板没有缩略图，使用其首页。 |
| `docs/<id>.<ext>` | 只读；白板彻底删除时一起删除。 |

服务端每 3 秒保存一次改动；关闭窗口或中断进程（Ctrl+C）时再保存一次。

### 只读白板

文件无法完整读出的白板（已损坏、部分内容无法读取，或由更新的版本写入）以只读白板打开。

- 能读出的内容正常显示，原文件不会被覆盖。每次打开同一块白板时，警告只出现一次。
- 拥有「管理白板」权限的设备在看过警告后，可以选择「仍然编辑」。原文件先复制到 `backups/locked/`。

详见 [docs/format.zh-CN.md](docs/format.zh-CN.md)。

### 备份

版本变更后首次启动时，应用先将 `boards/`、`index.sqlite`、`space.json` 和 `spaces/`（存在的才复制）复制到 `backups/upgrade/<时间>_<旧版本>_to_<新版本>/`，然后才处理其他文件。只保留最近 5 份。

从 1.0.x 升级到 1.1 时，存储目录要先转换（见 [docs/format.zh-CN.md](docs/format.zh-CN.md#读取-10x-的文件)），这时备份失败就不启动，并显示原因。不支持用 1.0.x 打开 2.0 转换过的存储目录；需要回到 1.0.x 时，使用 `backups/upgrade/` 中的副本。

升级前可以执行 `python tools/check_boards.py` 检查白板。

## 离线与重连

- 离线时书写的笔画暂存在本地和 IndexedDB 中，刷新页面不会丢失。重连后按顺序发送，服务端按笔画 id 去重。
- 重连的客户端发送其纪元和序号。服务端重启后纪元改变，服务端随即发送整块白板，因此 iPad 不会停留在过时或空白的内容上。
- 窗口尺寸或方向改变时重绘全部内容；平移和缩放时只重绘可见范围内的笔画。
- 生成缩略图时，按内容范围加上边距取景。

> **注意**
> `http://*.local` 不是安全上下文，因此无法使用 Service Worker，服务端未运行时 iPad 无法打开页面。页面打开期间服务端重启的情况已经处理。

## 故障排查

### 诊断面板

以下任一方式打开诊断面板：在 Mac 窗口中连点「连接其他设备」三下；在 iPad 上连点右上角的连接状态三下；在电脑上的浏览器中，断开连接时连点白板名称旁的红点三下；或在地址后添加 `?debug=1`。面板显示帧率与最长帧间隔、渲染耗时、采样率、落笔次数、被系统中断的笔画数、事件间隔、写盘耗时，以及 Pencil 倾角与 `altitudeAngle` 的原始读数和实际采用的角度。

诊断面板打开时，卡顿数据同时发送到 Mac 的终端；页面错误在任何情况下都会发送。请查看 Mac 终端或日志中以 `[诊断]` 开头的行：

| 现象 | 原因 |
| --- | --- |
| 「最长帧」长，「事件间隔」短 | 主线程被阻塞。 |
| 「最长帧」正常，「事件间隔」长或「中断」增加 | 系统手势占用了输入事件。 |

页面处于后台时 `requestAnimationFrame` 暂停；这类帧间隔不计入上报。

### 出现放大镜或笔画消失

页面已屏蔽文字选择和长按菜单，在捕获阶段取消触摸事件的默认行为（与 [excalidraw#4705](https://github.com/excalidraw/excalidraw/pull/4705) 的做法相同），并在落笔时清除选区。

**随手写**（Scribble）在系统层面运行，页面无法控制。它识别到手写文字时会接收 Pencil 输入，表现为笔画消失或出现选择界面。抬笔后迅速再次落笔最容易触发。关闭方法：

```
设置 → Apple Pencil → 随手写 → 关闭
```

连续三次被系统中断后，页面显示关于随手写的提示。「设置 → 辅助功能 → 缩放」（三指连点两下触发）会造成相同的影响，页面同样无法控制。

### 测试

CI 的每个 job 都有同名的 `make` 目标，本地运行的命令与 CI 相同：

```bash
make deps      # 测试依赖（从 requirements-test.lock 安装）和 Chromium
make lock      # 改了 requirements*.txt 之后重新生成锁文件（需要 uv）
make fast      # checks + unit + js，不开浏览器
make test      # checks、unit、js、inksync 和 e2e
make e2e PYTEST_ARGS="-k sync -x"
make webkit    # 在 WebKit 上运行冒烟用例（WB_BROWSER=webkit）
make plan FILES="whiteboard/app.py docs/sketch.md"   # 这些改动在 CI 里会跑哪些 job
```

- `make checks` 运行只开错误类规则（语法错误、未定义的名字）的 ruff，`CHANGELOG.md` 和提交说明的检查，以及依赖锁文件是不是最新的。

- 端到端测试在 `tests/e2e/`，按领域分文件（同步、输入、橡皮、白板列表、笔具盘……）；共用的 fixture 在 `conftest.py`，共用的函数在 `support.py`，页面里用的小工具（`window.__t`）在 `probe.js`。不需要页面的纯计算放在 `tests/js/`。
- 端到端测试打开两个浏览器页面（Mac 端和一台触摸设备）并在两者之间同步，覆盖书写、撤销、擦除、清空、Pencil 独占、切换白板、断线重连补发、文件夹、只读白板和导出对话框。未安装 Playwright 或浏览器时自动跳过。
- `tests/test_compat.py` 检查旧版本写出的白板文件现在能否读出相同的内容。不要用新代码重新生成 `tests/fixtures/compat/` 中的测试数据。

### 依赖

人改的是输入文件，安装一律用由它们生成的锁文件（`tools/lock_deps.py`，`uv pip compile --universal --generate-hashes`，一份锁同时适用于 macOS arm64 和 Linux x86_64）：

| 输入（改这里） | 锁文件（生成的） | 谁从它安装 |
| --- | --- | --- |
| `requirements.txt`（应用）+ `requirements-package.txt`（PyInstaller、cryptography） | `requirements.lock` | `package` 和 `updates` job |
| `requirements-test.txt` | `requirements-test.lock` | `make deps`、所有测试 job、Playwright 容器 |

测试的锁以 `requirements.lock` 为约束，两份锁里都有的包版本相同。从源码运行（`start-whiteboard.command`）仍然直接安装 `requirements.txt`。

添加或升级依赖：

1. 改输入文件。升级 Playwright 只改 `requirements-test.txt` 里 `playwright==` 那一行；CI 的容器镜像跟着锁文件里的版本走。
2. 运行 `make lock`（需要 [uv](https://docs.astral.sh/uv/)：`pip install uv` 或 `brew install uv`）。已经锁定的版本保持不变；`make lock LOCK_ARGS="--upgrade-package aiohttp"` 升级一个包，`LOCK_ARGS=--upgrade` 全部升级。
3. 输入文件和两份锁文件一起提交，单独成一个提交，CI 全绿后再合入。

`tests/test_dependency_lock.py`（属于 `make checks`）在输入改了而锁文件没有重新生成时失败。`package` job 把装进去的版本（`pip freeze`）写进运行摘要。

### 持续集成

只有一个工作流 `.github/workflows/ci.yml`。其中的 `plan` job（`tools/ci_plan.py`）按改动的文件挑选要跑的 job，运行摘要里列出每个 job 以及是哪个文件让它运行的。完整规则见 [docs/design/ci-and-updates.zh-CN.md](docs/design/ci-and-updates.zh-CN.md)。

| 改动 | 运行的 job |
| --- | --- |
| 只改文档 | `checks` |
| 应用或 inksync 的代码 | `checks`、`unit`、`e2e`、`webkit`、`package`（涉及时加上 `js`、`inksync`） |
| `ipad/` | `checks`、`ipad` |
| CI 本身，或无法识别的路径 | 全部 |
| 推送到 `dev`，或 `v*` tag | 全部，然后发布更新（`alpha` 或 `stable`） |

- 可以在提交说明里写 `[ci: e2e,webkit]` 或 `[ci: all]` 手动指定，也可以在手动运行时填写 `jobs`。
- 其他分支在 `package` job 的最后演练更新发布：用临时密钥生成增量包、核对签名，并把增量包应用到上一个构建上。
- 端到端测试失败时，每个打开的页面都会截图，上传为 `test-results-*` 产物。

## 不做的事

- **不设账号和密码。** 设计前提是家庭或办公室网络：能够访问 Mac 的设备即可书写。
- **两台设备。** 协议层面支持两台以上设备，但未经测试，也不作保证。
- **不复刻 iPad 的选择工具**，因为复刻需要美术素材。
