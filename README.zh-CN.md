# 局域网共享白板

供同一局域网内的 Mac 与 iPad 共同书写的手写白板。

[English](README.md) | 简体中文

## 概述

本应用运行在 Mac 上，向局域网提供手写白板页面。Mac 与 iPad 打开同一块白板，任一设备上的笔画都会实时显示在另一设备上。所有通信只在局域网内进行，不需要账号，也不使用云服务；唯一的对外连接是向 GitHub Releases 检查更新。

```
┌──────────── Mac ────────────┐            ┌─────── iPad ───────┐
│ pywebview 窗口（role=mac）  │            │ 主屏 Web Clip 图标 │
│   白板列表 / 背景           │  WebSocket │   全屏书写界面     │
│   缩放 / 导出 PNG           │◀──────────▶│   Apple Pencil     │
│ aiohttp 服务 + mDNS 广播    │   局域网   │                    │
│ 白板以矢量形式存储          │            │ IndexedDB 本地缓存 │
└─────────────────────────────┘            └────────────────────┘
```

## 功能

- **局域网实时同步。** Mac 提供页面并保存白板；局域网内的任何设备都可以在浏览器中打开页面并书写。
- **矢量笔迹。** 笔画以点的形式存储，而非图片。一条 500 个点的笔画通常小于 2 KB。轮廓由 [perfect-freehand](https://github.com/steveruizok/perfect-freehand) 生成。
- **Apple Pencil 输入。** 压感与倾角决定钢笔的粗细；Pencil 落下期间忽略手掌；未开启手指书写时，手指用于平移和缩放。
- **两种橡皮擦。** 对象橡皮擦删除所触及的笔画；像素橡皮擦只移除扫过的区域，笔迹仍为矢量。
- **三种白板**，其中文档板用于在 PDF 或图片上批注，并连同笔迹一起导出。
- **离线书写。** 笔画暂存在本地和 IndexedDB 中，连接恢复后按顺序发送。
- **权限。** 局域网内的任何设备都可以书写。管理白板、设置白板、清空白板和导出白板需要在 Mac 上分别授予。

## 运行要求

| 项目 | 要求 |
| --- | --- |
| 服务端 | macOS 11 或更高版本的 Mac。Release 只提供 Apple 芯片（`arm64`）版本；Intel 机型见[自行打包](#自行打包)。 |
| iPad | Safari。Apple Pencil 不是必需的，但输入处理针对它进行了调校。 |
| 网络 | 两台设备位于同一网络，且路由器未屏蔽 mDNS / Bonjour。 |
| 从源码运行 | Python 3.10 或更高版本（Release 使用 3.12 构建）。 |

## 安装

### 下载

1. 从仓库的 Releases 页面下载 `Whiteboard-<版本号>-macos-arm64.zip`。
2. 解压后将 **Whiteboard.app** 拖入「应用程序」文件夹。

首次打开时会出现两个系统提示，每个只出现一次。

| 提示 | 操作 |
| --- | --- |
| 「无法验证开发者」 | 应用只做了 ad-hoc 签名。右键点按应用，选择「打开」，再点按「打开」。此后可以直接双击打开。 |
| 「白板想要查找并连接到本地网络上的设备」 | 必须允许，否则 iPad 无法连接 Mac。该提示自 macOS 15 起出现。 |

### 更新

应用在启动时检查一次 GitHub Releases。存在新版本时，对话框显示版本号、更新说明和三个选项：

| 选项 | 结果 |
| --- | --- |
| 跳过这个版本 | 记录该版本号，此后不再提示该版本；更新的版本照常提示。 |
| 退出应用时安装 | 在后台下载，关闭窗口时替换应用。 |
| 安装并重启应用 | 立即替换并重新打开应用。 |

- 对话框左下角的「以后自动下载更新」**默认关闭**。关闭时，检查只获取版本信息；选择安装后才开始下载，进度显示在对话框中。
- 开启后，启动时发现的新版本会在对话框出现之前于后台下载。手动检查更新从不下载。
- 预发布版（带连字符的 tag，例如 `v1.0.0-rc.1`）不会推送给用户：检查读取的是 `releases/latest`。
- 更新包使用 `ditto` 解压。替换前检查可执行文件和代码签名，替换后再次检查签名。任一检查未通过时，恢复原有版本并重新打开。

「关于」面板（右上角最后一个图标）显示应用图标、名称、版本号和地址，提供「更新日志」「日志文件」链接，底部是「检查更新」按钮。检查结果显示在按钮上方：已是最新版本时附带版本号，失败时说明原因（无法连接、被限流、没有适用于本机的安装包）。

### 从源码运行

```bash
git clone https://github.com/Maimai-l/white-board.git
cd white-board
```

| 脚本 | 作用 |
| --- | --- |
| `start-whiteboard.command` | 首次运行时创建运行环境并安装依赖；之后直接打开窗口。 |
| `browser-mode.command` | 执行 `start-whiteboard.command --headless`：只运行服务端，通过浏览器访问。 |
| `update.command` | 执行 `git pull --ff-only`；依赖有变化时在下次启动时安装。 |

> **注意**
> 如果 macOS 拒绝打开脚本（提示「身份不明的开发者」），右键点按脚本，选择「打开」，再点按「打开」；或者执行一次 `xattr -dr com.apple.quarantine <仓库文件夹>`。

手动运行：

```bash
pip install -r requirements.txt
python run.py                 # 打开 Mac 窗口，同时在局域网上提供服务
```

| 参数 | 作用 |
| --- | --- |
| `--headless` | 只运行服务端，不打开窗口。 |
| `--port 9000` | 使用其他端口（默认 8848）。端口被占用时依次尝试下一个，最多 20 次。 |
| `--data-dir DIR` | 将白板存储在其他目录。 |
| `--mdns` | 额外注册 `_http._tcp` 服务。在 macOS 上默认由系统负责。 |
| `--no-mdns` | 不注册 `_http._tcp` 服务。 |
| `--no-bonjour` | 不注册 iPad 外壳使用的 `_whiteboard._tcp` 服务。 |
| `--debug` | 开启调试日志和开发者工具。 |
| `--version` | 显示版本号。 |

> **注意**
> `--port` 和 `--data-dir` 只对本次运行有效，不写入配置。如需长期更换存储目录，请在白板设置中选择。因端口被占用而顺延的端口同样只用于本次运行，下次启动时仍从配置的端口开始尝试。

窗口右上角的 iPad 按钮显示 iPad 应访问的地址，格式为 `http://你的电脑名.local:8848/`。

### 自行打包

推送 tag 会构建并发布 Release，其中包含同一版本的 iPad 外壳 IPA：

```bash
git tag v1.1.0 && git push origin v1.1.0
```

也可以在 Actions 页面手动运行「打包 macOS 应用」工作流；手动运行只生成构建产物，不发布 Release。本地打包：

```bash
pip install pyinstaller
python packaging/make_icns.py packaging/whiteboard.icns
WHITEBOARD_VERSION=1.1.0 pyinstaller --noconfirm packaging/whiteboard.spec
```

- 本地打包只有在 `packaging/ipad/Whiteboard.ipa` 存在时才包含 iPad 外壳；否则安装页会指向 Release 下载。
- Intel 版本需要在 Intel Mac 上本地打包，或在 `.github/workflows/build-macos.yml` 中增加 `macos-13` / `x86_64` 矩阵项。
- 将预发布版转为正式版之前，按照 [docs/release-checklist.zh-CN.md](docs/release-checklist.zh-CN.md) 逐项检查。

打包后的应用与源码运行共用 `~/Library/Application Support/Whiteboard`，两者之间切换不会丢失白板。打包后的应用将日志写入 `~/Library/Logs/Whiteboard.log`。

## 连接 iPad

### 主屏描述文件

1. 在 Mac 窗口中点按右上角的 iPad 图标（「连接 iPad」），再点按卡片上的下载按钮，获得 `whiteboard.mobileconfig`。也可以在 iPad 的 Safari 中直接打开 `http://你的电脑名.local:8848/profile.mobileconfig`。
2. 在 iPad 上打开该描述文件，然后进入「设置」→「已下载描述文件」→「安装」。描述文件未签名，确认安装即可。
3. 主屏上出现「白板」图标。点按后以全屏打开白板，不显示 Safari 的地址栏。

描述文件使用 `.local` mDNS 主机名，因此 Mac 的 IP 地址变化后无需重新安装。该主机名由 macOS 自带的 Bonjour 服务发布；`--mdns` 只是为发现工具额外注册 `_http._tcp` 服务，注册失败不影响使用。

### iPad 外壳

iPad 外壳是可选的原生应用，内含一个 `WKWebView`。它加载 Mac 上的同一个页面，并把 UIKit 的 Pencil 采样点传给页面。白板的全部逻辑都在页面中，因此 Mac 端更新后，外壳在下次打开时即使用新的行为。

| 输入途径 | 每秒新的 Pencil 位置 | 坐标 | 预测采样点 |
| --- | --- | --- | --- |
| Safari | 约 60 个 | 整数 | 无 |
| iPad 外壳 | 约 240 个 | 带小数 | 有 |

外壳通过 TrollStore 安装，因此 iPad 的系统版本必须在 TrollStore 支持的范围内：iPadOS 14.0 beta 2 至 16.6.1、16.7 RC 或 17.0。没有 TrollStore 时请使用主屏描述文件，功能相同。

1. Mac 窗口中的「连接 iPad」卡片显示外壳安装页地址 `http://你的电脑名.local:8848/ipad`。在 iPad 的 Safari 中打开该地址。
2. 在 TrollStore 的设置中开启 URL Scheme，然后点按「安装白板外壳」。
3. 打开外壳。局域网中只有一台 Mac 时直接连接；有多台时列出供选择。路由器屏蔽 Bonjour 时，回到安装页点按「打开外壳」。

- **更新。** Mac 更新后，外壳在下次启动时提示更新，并将安装包交给 TrollStore 安装。
- **更换 Mac。** 在白板设置中使用「换一台 Mac」，或在 iPadOS「设置」App 的「白板」中开启「重新查找 Mac」。两种方式下外壳都会列出找到的 Mac，即使只有一台，以便确认。
- **发现。** Mac 通过系统的 mDNS 服务注册 `_whiteboard._tcp`。`--no-bonjour` 关闭该注册，此后只能从安装页进入外壳。
- **导出。** 外壳将导出的文件作为下载接收，并打开系统分享面板，可存入「文件」或发送。

设计与验收标准见 [docs/ipad-shell.zh-CN.md](docs/ipad-shell.zh-CN.md)。

## 使用

### 工具栏

iPad 使用**笔具盘**；其他设备使用**普通工具栏**。满足以下任一条件的设备视为 iPad：User-Agent 含 `iPad`；报告 `Macintosh` 且触摸点多于一个（iPadOS 的 Safari 使用桌面版 User-Agent）；页面运行在 iPad 外壳中。两种工具栏之间不能切换。

| | 笔具盘（iPad） | 普通工具栏（其他设备） |
| --- | --- | --- |
| 工具 | 钢笔、马克笔、荧光笔、橡皮擦；每件工具分别记录颜色和粗细 | 钢笔、马克笔、荧光笔、橡皮擦 |
| 其他控件 | 撤销、重做；「⋯」菜单中有自动最小化、手指书写和清空白板 | 工具栏位置、颜色、粗细、撤销、重做、清空白板；触摸设备上另有手指书写开关 |
| 位置 | 停靠在四条边中的任意一条，或在角落缩为圆形 | 上边或下边，记录在本机；面板向远离边缘的方向展开 |

工具栏周围：

- **右上角按钮组：** 白板、白板设置和导出。Mac 窗口中另有「连接 iPad」和「关于」。触摸设备上该组使用强调色图标。每一项只在设备拥有相应权限时显示。
- **右下角按钮组（仅 Mac）：** 放大、回到内容、缩小。
- **连接状态圆点（左上角）：** 绿色表示已连接，黄色表示同步中，红色表示已断开。连点三下打开诊断面板。

笔具盘采用 [static/vendor](whiteboard/web/static/vendor/README.md) 中的实现，并增加了以下功能：

- 点按正在使用的工具打开粗细面板；点按彩虹色块打开完整的取色器（色板、色谱、滑块）。
- 拖动握把可将笔具盘停靠到四条边中的任意一条；上边沿用下边的布局，面板向下展开。在某条边的触发区内停留 250 ms 后，该边成为停靠目标。快速拖动后松手时，笔具盘按惯性越过松手位置继续移动；动画可在任意时刻中断。相关参数位于 `static/js/pkpicker.js` 顶部的 `TUNING`。
- 放到角落时，笔具盘缩为显示当前工具的圆形，Pencil 或光标靠近时自动展开。手指没有悬停状态，需点按圆形。
- 撤销和重做使用白板自身的历史记录，按钮状态随之变化。
- 白板选择界面或设置面板打开时，笔具盘隐藏。
- 未使用原实现自带的画布、直尺和套索。不透明度不可用，因为笔画格式中没有对应字段。

界面采用系统控件的样式：磨砂玻璃和系统蓝强调色。书写期间关闭背景模糊。笔具盘始终不使用磨砂效果，因为它位于书写区域之上。

### Pencil、手指与手掌

| 输入 | 行为 |
| --- | --- |
| Apple Pencil | 书写。默认只有 Pencil 可以书写。 |
| 手指（默认） | 单指或双指平移、缩放。 |
| 手指（开启手指书写） | 单指书写，双指平移、缩放。第二根手指落下时，撤回刚开始的笔画。该设置记录在本机。 |
| 手掌 | Pencil 落下期间及抬起后 0.5 s 内忽略。手掌先于 Pencil 接触屏幕造成的位移，在 Pencil 落下时撤回。 |

- 钢笔的粗细随压感和倾角变化。马克笔和荧光笔粗细一致；荧光笔半透明。
- 压感曲线按 iPad 实际报告的范围拟合：一整行手写的压感落在 0 至 0.13 之间。见 [docs/format.zh-CN.md](docs/format.zh-CN.md)。
- 页面在画布上屏蔽 Safari 的文字选择、查询和长按手势，否则快速书写时这些手势会接管笔画。
- 文本输入框（白板名称、搜索、文件夹名称）可以正常输入文字。

### 橡皮擦

在橡皮擦面板中选择橡皮擦；选择记录在本机。两种橡皮擦都不能手动调节粗细。粗细以屏幕像素为单位，因此放大后擦除范围更精细。

| 橡皮擦 | 行为 | 直径 |
| --- | --- | --- |
| 对象橡皮擦（默认） | 删除所触及的笔画。若该笔画已被像素橡皮擦分成多段，只删除触及的那一段。 | 6，与角度无关 |
| 像素橡皮擦 | 移除扫过的区域，保留其余部分。 | 由 Pencil 落下时笔身与屏幕的夹角决定 |

像素橡皮擦的直径取自 `packages/inksync/inksync/web/input-erase.js` 中的 `ERASER_CURVE`，数值根据原生 PencilKit 测得。表中各点之间按线性插值。

| 笔身与屏幕的夹角 | 90° | 80° | 68°–37° | 35° | 32° | 28° | ≤ 25° |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 直径（屏幕 px） | 6 | 7.5 | 16.5 | 35 | 52 | 75 | 81 |

- 粗细在 Pencil 落下时确定，同一笔画内不再变化；悬停时的光标圈仍随倾角变化。常规握笔姿势约为 50°，对应直径 16.5。鼠标和手指没有倾角，使用 50° 对应的数值。
- 夹角根据 `tiltX` / `tiltY`（Pointer Events Level 2）按规范附录中的公式计算。只有两者都为 0 时才使用 `altitudeAngle`，因为不支持倾角的浏览器会将其报告为 π/2（竖直）。
- 像素橡皮擦将扫过的区域作为遮罩记录在笔画上（文件格式中的 `m` 字段）。渲染和导出 PDF 时从轮廓中减去遮罩，因此笔迹保持矢量。
- 某条笔画的遮罩在抽稀后仍超过上限时，该笔画被替换为剩余的若干段，并保留原有的层叠顺序。一次拖动为一个撤销步骤。

擦除的开销取决于扫过的区域，与笔画总数无关：笔画按 256 单位的网格建立空间索引，只重绘脏矩形，一次拖动产生的操作每帧发送一次。脏矩形重绘的结果与整屏重绘逐像素一致。

| 白板规模 | 橡皮擦 | 擦除一次，优化前 → 优化后 |
| --- | --- | --- |
| 3000 条笔画 | 对象橡皮擦 | 438 ms → 4.4 ms |
| 3000 条笔画 | 像素橡皮擦 | 465 ms → 13 ms |
| 6000 条笔画 | — | 854 ms → 28 ms |

测量方法与细节见 [docs/eraser.zh-CN.md](docs/eraser.zh-CN.md)、[docs/format.zh-CN.md](docs/format.zh-CN.md)。

### 鼠标、触控板与键盘

| 输入 | 操作 |
| --- | --- |
| 左键 | 书写 |
| 中键、右键或按住空格键 | 平移 |
| 滚轮 | 滚动 |
| ⌘ / Ctrl + 滚轮 | 缩放 |
| 触控板双指捏合 | 缩放 |
| `⌘Z` | 撤销 |
| `⌘⇧Z` / `⌘Y` | 重做 |
| `⌘0` | 适应窗口 |
| `⌘+` / `⌘-` | 放大 / 缩小 |

- 双指捏合缩放同时支持两种事件：Chrome 和 Firefox 发送 `ctrl + wheel`；WebKit（Safari 以及打包应用中的 `WKWebView`）发送 `gesturestart` / `gesturechange` / `gestureend`。在滚轮事件中，单次 `deltaY` 限制在 25 以内，因为触控板每次只报告几个像素，而鼠标滚轮每格报告 100。
- 文本输入框获得焦点时，快捷键和按住空格键平移均不生效，此时 `⌘Z` 撤销的是输入的文字。
- 白板设置中可以更换背景（空白、方格、横线、点阵）和存储目录，以及授予其他设备权限。
- 清空白板（「清空白板？」）和删除白板（「删除白板？」）前会请求确认；确认按钮使用警示色。

### 白板类型

白板类型在新建时选定，之后不能更改。

| 类型 | 范围 | 初始视图 |
| --- | --- | --- |
| 大白板 | 四个方向无限延伸；缩放范围 0.05×–8× | Mac 上适应内容，iPad 上 1:1 |
| 笔记 | 宽度为一页（1000 单位），向下无限延伸 | 页宽，位于页首 |
| 文档板（beta） | 范围固定，由 PDF 或图片生成 | 页宽，位于首页 |

- 在笔记中，不能在页面之外书写；在页边拖动即翻页，视图不能越过页首。
- 翻页速度超过约 350 px/s 时按惯性继续移动。一页接近占满屏幕宽度时，松手后缩放自动对齐到页宽。
- 右下角按钮组中间的按钮用于回到内容。

### 白板选择界面

点按右上角按钮组的第一个图标（「白板」）打开白板选择界面：满屏显示缩略图，每张标有白板类型；「＋」用于新建白板（先选择类型）或文件夹。

- **名称与时间。** 缩略图下方显示名称和最后一次书写的时间。当天只显示时刻；当年不显示年份。
- **默认名称。** 未命名的白板以灰色显示默认名称（「白板」「笔记」「文档」）。由 PDF 或图片创建的白板以原文件名（不含扩展名）命名。
- **重命名。** 点按名称即可编辑。按回车键或点按其他位置确认，按 Esc 键取消，清空名称则恢复默认名称。输入法组字期间的回车键和 Esc 键由输入法处理。任何白板都可以在不切换到该白板的情况下重命名；重命名只广播列表。
- **搜索。** 搜索框匹配名称、默认名称、文件夹名称和文档的原文件名。搜索范围是全部白板，结果不分文件夹列出。按 Esc 键清空搜索，不关闭界面。
- **再次打开。** 白板选择界面打开时显示当前白板所在的层级。

**拖动**在手指、Pencil、鼠标和触控板上的行为相同。卡片从网格中浮起并跟随指针移动，空位表示松手后的位置。

| 指针 | 开始拖动的条件 |
| --- | --- |
| 鼠标、触控板 | 指针移动数个像素。 |
| 手指、Pencil | 横向移动（列表只能纵向滚动），或按住卡片不动 220 ms。纵向滑动为滚动列表。 |

| 放置位置 | 结果 |
| --- | --- |
| 文件夹卡片的中部 | 将白板移入该文件夹。文件夹卡片的边缘不计。 |
| 返回按钮或文件夹栏（在文件夹内） | 将白板移出文件夹。 |
| 两块白板之间 | 调整顺序。只有指针在同一位置停留后，其他卡片才会让位。 |
| 靠近上边或下边 | 滚动列表。 |

- 顺序保存在 Mac 上的 `space.json` 中，因此所有设备上一致，重启后保留。文件夹按名称排序，不参与拖动排序。
- 拖动基于指针事件实现，未使用浏览器的拖放功能，因为 iOS Safari 不支持该功能。时间参数和弹簧曲线位于 `static/js/dragsort.js` 开头。
- `static/lab/drag.html` 是用于在 iPad 上调整上述参数的独立页面。它只在从源码运行时可用；打包后的应用不包含 `static/lab/`。

**文件夹**只有一层，与白板显示在同一网格中。打开文件夹后只显示其中的白板。

- 新建文件夹：在新建白板对话框中选择文件夹项（仅在最外层提供）。与访达相同，新文件夹的名称框直接进入编辑状态并选中默认名称：输入名称后按回车键或点按其他位置即完成。按 Esc 键保留默认名称「未命名文件夹」；名称已存在时显示提示并保持编辑状态。
- 将白板归入文件夹：把白板拖到文件夹上；或点按名称旁的文件夹图标，选择现有文件夹或输入新名称（即新建文件夹）。
- 文件夹以名称作为标识。重命名文件夹会同时修改其中每块白板记录的文件夹名称；不能使用已存在的名称。
- 在文件夹内新建的白板保留在该文件夹中。拖入窗口或从访达打开的 PDF 和图片放入白板选择界面当前显示的文件夹；白板选择界面关闭时，放入当前白板所在的文件夹。
- 删除文件夹不会删除其中的白板；这些白板移到文件夹之外。

### 文档（PDF 与图片）

将 PDF 或图片拖入 Mac 窗口、在新建白板对话框中选择文档项，或在访达中用本应用打开文件，即可新建文档板（beta）。页面依次排列在画布上，已连接的设备同步切换到新白板。

**从访达打开文件。** 打包后的应用出现在 PDF、png、jpeg、gif、bmp、webp 和 tiff 文件的「打开方式」中，作为备选应用，不改变系统默认的打开方式。`.wbz` 文件归本应用所有，双击即可打开。

| 文件 | 结果 |
| --- | --- |
| PDF 或图片 | 新建文档板，与拖入窗口相同。 |
| 当前存储目录中的 `.wbz` | 切换到该白板。 |
| 其他 `.wbz`（例如 `backups/` 中的文件） | 导入为新白板，原文件不作修改。无法完整读取的白板以只读方式打开。文档板还需要同一存储目录的 `docs/` 中存有原件。 |

| 项目 | 说明 |
| --- | --- |
| 格式 | PDF、png、jpg/jpeg、gif、bmp、webp、tif/tiff |
| 限制 | 最多 400 页；上传文件最大 256 MB |
| 不支持 | 设有密码的 PDF |
| 原件 | 原样复制到存储目录的 `docs/` 中，不作任何修改 |
| 笔迹 | 以矢量数据保存在白板的 `.wbz` 文件中；不能写在页面之外；视图止于首页和末页 |
| 页面图像 | 由 Mac 按缩放档位渲染，只渲染可见的页面 |

右上角按钮组的第三个图标用于导出文档：PDF 导出为 PDF，图片导出为图片（gif、bmp、webp 和 tiff 导出为 PNG）。

- 笔迹以矢量形式追加，原有内容不重新编码。每条笔画使文件增大数百字节；批注较多的讲义增大数百 KB。
- 两页之间空隙中的笔迹归入较近的一页；页面之外的笔迹被裁掉。

## 其他设备的权限

任何打开该地址的设备都可以书写。其他所有操作都需要在 Mac 的白板设置中逐项授予，默认均不授予。

| 权限 | 允许的操作 | 服务端检查位置 |
| --- | --- | --- |
| 管理白板 | 切换、新建、删除、重命名、归入文件夹、由 PDF 或图片新建 | `/api/info`、`/api/boards`、`/api/thumb`、`/api/doc` 上传，以及对应的 WebSocket 操作 |
| 设置白板 | 更换背景 | `meta` 操作 |
| 清空白板 | 一次清除整块白板 | `clear` 操作 |
| 导出白板 | 下载整块白板，包括原件 | `/api/export` |

- 权限根据 TCP 对端地址判断。回环地址和 Mac 自身的局域网地址拥有全部权限。不使用 User-Agent 和 WebSocket 握手中的 `role`，因为客户端可以任意填写这两项。WebSocket 的权限在连接建立时确定。
- 书写始终允许：页面、WebSocket、页面图像、描述文件和诊断上报不需要权限。
- 页面通过 `data-perms` 属性获得已授予的权限，只显示允许的入口。这只影响显示；权限由服务端检查。
- 检查更新和选择存储目录通过本机的 pywebview 接口进行，其他设备无法访问。因此「关于」和「连接 iPad」只出现在 Mac 窗口中。

## 数据

### 存储结构

默认存储目录为 `~/Library/Application Support/Whiteboard/boards-data`，可在白板设置中更改。

```
boards-data/
  boards/<id>.wbz        每块白板一个文件
  index.sqlite           白板列表的索引（可重建）
  space.json             顺序、文件夹名称和当前白板
  spaces/<应用名>/        已安装应用的白板，结构同上
  apps/<应用名>/          已安装的应用（见 docs/embed.zh-CN.md）
  thumbs/<id>.png        白板选择界面的缩略图
  docs/<id>.<ext>        文档板的原件
  backups/upgrade/       新版本首次运行前的副本
  backups/locked/        编辑只读白板前的副本
```

| 路径 | 说明 |
| --- | --- |
| `boards/<id>.wbz` | 点经过量化、增量编码和 varint 编码；文件整体经 zlib 压缩。格式见 [docs/format.zh-CN.md](docs/format.zh-CN.md)。 |
| `index.sqlite` | 删除后下次启动时从 `.wbz` 文件重建。启动时按修改时间核对文件与索引，应用关闭期间被改动或放入的文件也会更新到索引中。 |
| `space.json` | 顺序、文件夹名称和当前白板。删除后顺序按更新时间排列；包含白板的文件夹可以恢复，空文件夹不能恢复。 |
| `spaces/<应用名>/` | 删除应用（`apps/<应用名>/`）后保留，重新安装同名应用后恢复。 |
| `thumbs/<id>.png` | 由 Mac 上传。文档板没有缩略图，使用其首页。 |
| `docs/<id>.<ext>` | 只读；随白板一起删除。 |

服务端每 3 秒保存一次改动；关闭窗口或中断进程（Ctrl+C）时再保存一次。

### 只读白板

文件无法完整读出的白板（已损坏、部分内容无法读取，或由更新的版本写入）以只读白板打开。

- 能读出的内容正常显示，原文件不会被覆盖。每次打开同一块白板时，警告只出现一次。
- 拥有「管理白板」权限的设备在看过警告后，可以选择「仍然编辑（先备份原文件）」。原文件先复制到 `backups/locked/`。

详见 [docs/format.zh-CN.md](docs/format.zh-CN.md)。

### 备份

版本变更后首次启动时，应用先将 `boards/`、`index.sqlite`、`space.json` 和 `spaces/`（存在的才复制）复制到 `backups/upgrade/<时间>_<旧版本>_to_<新版本>/`，然后才处理其他文件。只保留最近 5 份。

从 1.0.x 升级到 1.1 时，存储目录要先转换（见 [docs/format.zh-CN.md](docs/format.zh-CN.md#读取-10x-的文件)），这时备份失败就不启动，并显示原因。不支持用 1.0.x 打开 2.0 转换过的存储目录；需要回到 1.0.x 时，使用 `backups/upgrade/` 中的副本。

升级前可以执行 `python tools/check_boards.py` 检查白板。

## 离线与重连

- 离线时书写的笔画暂存在本地和 IndexedDB 中，刷新页面不会丢失。重连后按顺序发送，服务端按笔画 id 去重。
- 重连的客户端发送其纪元和序号。服务端重启后纪元改变，服务端随即发送整块白板，因此 iPad 不会停留在过时或空白的内容上。
- 窗口尺寸或方向改变时重绘全部内容；平移和缩放时只重绘可见范围内的笔画。
- 导出 PNG 和生成缩略图时，按内容范围加上边距取景。空白板导出为一屏大小的空白页面。

> **注意**
> `http://*.local` 不是安全上下文，因此无法使用 Service Worker，服务端未运行时 iPad 无法打开页面。页面打开期间服务端重启的情况已经处理。

## 故障排查

### 诊断面板

连点连接状态圆点三下，或在地址后添加 `?debug=1`，即可打开诊断面板。面板显示帧率与最长帧间隔、渲染耗时、采样率、落笔次数、被系统中断的笔画数、事件间隔、写盘耗时，以及 Pencil 倾角与 `altitudeAngle` 的原始读数和实际采用的角度。

诊断面板打开时，卡顿数据同时发送到 Mac 的终端；页面错误在任何情况下都会发送。请查看 Mac 终端或日志中以 `[诊断]` 开头的行：

| 现象 | 原因 |
| --- | --- |
| 「最长帧」长，「事件间隔」短 | 主线程被阻塞。 |
| 「最长帧」正常，「事件间隔」长或「中断」增加 | 系统手势占用了输入事件。 |

页面处于后台时 `requestAnimationFrame` 暂停；这类帧间隔不计入上报。

### 出现放大镜或笔画消失

页面已屏蔽文字选择和长按菜单，在捕获阶段取消触摸事件的默认行为（与 [excalidraw#4705](https://github.com/excalidraw/excalidraw/pull/4705) 的做法相同），并在落笔时清除选区。

**随手写**（Scribble）在系统层面运行，页面无法控制。它识别到手写文字时会接收 Pencil 输入，表现为笔画消失或出现选择界面。抬笔后迅速再次落笔最容易触发。关闭方法：

```
设置 → Apple Pencil → 随手写 → 关闭
```

连续三次被系统中断后，页面显示关于随手写的提示。「设置 → 辅助功能 → 缩放」（三指连点两下触发）会造成相同的影响，页面同样无法控制。

## 不做的事

- **不设账号和密码。** 设计前提是家庭或办公室网络：能够访问 Mac 的设备即可书写。
- **两台设备。** 协议层面支持两台以上设备，但未经测试，也不作保证。
- **不复刻 iPad 的选择工具**，因为复刻需要美术素材。
